DETERMINISTIC PRECEDENCE (never first-row-wins)
1. Option identity first: an option-specific policy wins over the service-level policy; the
   service-level policy is the documented fallback only when no option-specific policy matches.
2. Deepest destination scope wins: ServiceArea > City > AdministrativeArea > Country.
3. Ambiguity fails closed: two equally specific active policies produce the stable error code
   shipping.packaging.policy.ambiguous and ZERO fee is claimed - never an arbitrary pick.
Zero default: no matching policy yields shipping.packaging.not_configured with fee 0, never a hidden
extra charge. An explicitly configured zero-fee policy is still an explicit charged component.

MISSION B - PAYER MODE SEMANTICS (PERSISTED)
ShippingFreightPayerMode { Prepaid = 0, CollectOnDelivery = 1 } is a stable enum persisted as an
integer code with a SQL CHECK constraint (freight_payer_mode IN (0,1)), so no row can exist with no
responsible paying party. Free-form Persian strings are never stored. Prepaid means freight is payable
at checkout by the customer; CollectOnDelivery means freight is collected by the carrier/recipient at
delivery. Shipping states WHO owes freight and WHEN - it creates no Payment transaction and no
settlement. An omitted value persists as Prepaid, preserving legacy checkout behaviour exactly.
ShippingPackagingChargePayer.Checkout exists as a single-value contract so a carrier can never be
recorded as collecting a packaging fee. Order, Checkout, Payment and Settlement were not touched.
