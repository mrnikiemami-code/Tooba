MEASURED DEFECTS (source-confirmed before repair):
    A FulfillmentDirectory.Returns.cs returned ANY existing resend that carried the dispatch key BEFORE comparing the
      requested source/group/quantity, and a blank key silently took a non-idempotent path — so a changed request
      could receive another intent's parcel and a missing key could allocate twice.
    B post-dispatch-exception-dialog.tsx reset its drafts and minted a fresh occurrence in an effect keyed on
      [open, mode, parcelKey, lines]; a lines rerender, a close/reopen or a remount after an uncertain response could
      therefore produce a SECOND operation.
    C FulfillmentUnit.ReturnedUsableQuantity/ResendCommittedQuantity pooled one order line across every receipt of the
      unit, and CreateResendShipment replaced a returned resend with its chain root — so parcel A could borrow parcel
      B's returned units and the immediate physical lineage was lost.
    D ShipmentReturnReceipt de-duplicated by OrderLineId alone, so one parcel line could not be received as
      usable+damaged (3 units = 2 usable + 1 damaged).

LANDED:
    A + C — `FulfillmentUnit.CreateResendShipment` now requires a non-empty occurrence
      (`fulfillment.resend.occurrence_required`), replays a RECORDED occurrence BEFORE any capacity gate, and answers
      that occurrence only for the SAME source parcel, shipping group, effective method and canonical per-line
      quantities (`fulfillment.resend.intent_conflict` otherwise, zero new rows). A cancelled recorded resend keeps its
      history and is `fulfillment.resend.occurrence_cancelled` — never silently recreated. An empty server actor is
      refused (`fulfillment.resend.actor_required`). Capacity is now `ReturnedUsableQuantity(sourceShipmentId, line)`
      and `ResendCommittedQuantity(sourceShipmentId, line)` with `ResendableQuantity(sourceShipmentId, line)`, so a
      sibling returned parcel contributes nothing; a resend of a resend links its IMMEDIATE returned source
      (`ResendOfShipmentId`) and the ancestor chain stays readable (no root substitution, no double customer delivery).
      The directory no longer pre-empts the aggregate: it diffs the shipment-id set and treats an already-recorded id
      as a pure replay (rollback, no allocation). Fresh 257 packed−shipped−open quantity is untouched, resend never
      consumes the inventory reservation twice, no ordered/packed inflation, no lifetime-shipped decrement.
    B — new feature-owned `features/order-operational-groups/session/post-dispatch-attempt-store.ts` persists the
      COMPLETE reviewed envelope (code + selections/receipt lines + note + occurrence key + attempts) scoped to
      viewerScopeKey:checkoutId:fulfillmentId:sourceShipmentId:mode BEFORE the first POST. The dialog initialises once
      per scope signature, so a lines rerender never resets an open review or mints another occurrence; a synchronous
      `useRef` single-flight guarantees one mutation per same-tick submit; ANY non-authoritative outcome
      (timeout/network/5xx/typed refusal) retains the exact envelope; close/reopen/remount restores it and offers a
      read-only description plus ONE submit that reconciles it verbatim — even when fresh capacity is now false. Only
      an authoritative completion clears it, and only then may a new review mint a new occurrence. A viewer switch
      never inherits another viewer's attempt; unavailable storage degrades to "no retained review" and never to a
      blind remint. One concise inline localized error; no raw diagnostics, no extra page, no input outside the dialog.
    D — `ShipmentReturnReceipt` now de-duplicates on `(OrderLineId, Condition)` and validates the SUM across conditions
      against what THIS parcel line actually carried, so usable2 + damaged1 on a 3-unit line is representable and
      grants exactly 2 resendable units; a duplicate (line, condition), a foreign line, a non-positive quantity and an
      aggregate excess are all typed refusals. Replay compares the complete canonical receipt
      (`fulfillment.return.receipt_conflict` on any changed quantity/condition) and a changed receipt adds no capacity.
    Durable operator audit — a new additive fulfillment migration records `created_by_user_id`,

      `ux_shipment_return_receipt_items_line_condition`; the previously ignored actor arguments are now persisted, and
      the exact replay of a non-delivery no longer reattributes the operator fact.
