ROOT CAUSE — HYPOTHESIS CONFIRMED
ReservationPolicyDraft (reservation-policy-editor.tsx:10-18) has three string fields (initial/retry/max) and three boolean fields (inheritInitial/inheritRetry/inheritMax). The descriptor array at line 57 annotated its key as `keyof ReservationPolicyDraft`, which includes the boolean keys, so `draft[key]` widened to `string | boolean`. At line 112 that value is passed to `value={draft[key]}` on <input type="text">, whose value accepts string | number | readonly string[] | undefined -> TS2322. The compiler demonstrated the impossible branch itself: "Type 'false' is not assignable to ...". All three descriptors in the literal are string keys at runtime; the widening was purely a declaration defect. Every producer/consumer was verified before editing: the only read of `key` is the single fields.map, and nothing ever pushes a boolean key into `fields`.

ACTUAL REPAIR
Added a local, unexported, fully erased type alias and narrowed only the descriptor key annotation:
  type ReservationPolicyValueKey = "initial" | "retry" | "max";
  const fields: Array<{ key: ReservationPolicyValueKey; field: ReservationPolicyFieldView; unitFa: string; unitEn: string }> = [ ... ];
plus a short comment explaining the string/boolean split. No BLOCKED_ARCHITECT_DECISION raised: the declared mapping supports the repair with zero runtime change.
Why a literal union rather than a mapped derivation: a mapped `Draft[K] extends string ? K : never` form would silently admit any future string-valued field into the descriptor key space — the exact class of drift that caused this defect.
