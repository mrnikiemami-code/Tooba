## Authorization boundary (fail-closed, existing platform seams only)

`ShippingAdminAuthorizer` / `GeographyAdminAuthorizer`:

* gate 1: `IAdminPanelAccess.RequireAuthorizedAsync(request, ct)` — the same Host-owned seam every other
  admin authorizer uses; server-derived actor + tenant, not a route/body identifier;
* gate 2: `IAuthorizationService.CanAsync(Subject=user, Resource=permission#<id>, check)` where
  `Allow` passes, `Unavailable` throws `admin.authorization.unavailable` (fail-closed 503),
  anything else throws `admin.authorization.denied` (403).

`AdminPanelAccess` (Host) documents the Development-only actor header `X-Tooba-Dev-Actor-User-Id`
(ignored outside Development) — the existing contract used by Development tooling; no bypass exists for
the capability check that follows it.
