## 3. Root cause of the first two failed startup attempts (disclosed, not a repo defect)

The first two clone attempts failed with `Development seed requires Active tenant store-alpha`. The cause was
**stale environment variables left in my own shell session by an earlier unrelated task (046)**:

```text
Tooba__Edition=SingleStore
Tooba__DeploymentId=geo046-verify
Tooba__SingleStore__Tenants__0__TenantId=geo046
Tooba__SingleStore__Tenants__0__Status=Active
Tooba__SingleStore__Tenants__0__ConnectionReference=geo046scratch

```

Environment-variable configuration overrides the JSON tenant array, so the process saw a single tenant
`geo046` and no `store-alpha`. After clearing every `Tooba__*`/`ASPNETCORE_*` variable from the session the
same binary started normally (section 2). No repository file, migration, appsettings or Host configuration
was at fault, and none was changed. The stale password-bearing variable was removed as part of cleanup
(session leftover count after cleanup = 0).
