2) TRUE multilingual name editing (new shipping-method-language-model.ts + flat-method-language-editor.tsx)
- Languages come ONLY from the authoritative Admin registry (GET /v1/admin/languages via the existing
  features/admin-languages boundary). Live proof: فارسی / English / Русский with their real GUIDs and
  native names; rows without a real languageId are dropped; NO hardcoded fa/en/ru anywhere in code.
- Prefill from real server translations per language; missing translation is shown explicitly as
  «بدون ترجمه» (Русский in the live check) and the completeness summary reads «ترجمهشده: 2 از 3».
  No synthetic translation is ever created; an empty translation stays empty.
- Save writes ONLY the selected method + selected language through the unchanged canonical seam
  PUT /v1/admin/shipping-services/shipping-methods/one-level/{methodCode}/translations/{languageId}.
  The canonical methodCode is never changed by a name edit; a server answer is accepted only if the
  returned method+language equals the requested target (stale/out-of-order responses cannot land on
  another method or language).
- Explicit states for loading / denied / error-with-retry / empty registry; blank and over-length names
  are rejected by the existing validator before any request; «بازگردانی» reverts a draft.
- Lossless language switching: per-language drafts are kept, so unsaved text survives switching
  (live proof: Russian draft preserved, then Persian, then back to Russian with «Экспресс тест» still
  present); an explicit «پیشنویس ذخیرهنشده در N زبان» indicator appears. dir follows each language
  (ltr for Russian, rtl for Persian). No data loss observed.
- Name save refreshes the source of truth in place (dialog stays open, new value appears without
  reopening); activation keeps its previous close-after-save behaviour.

3) Separate, honest statuses (no invented readiness)
- METHOD ACTIVE/INACTIVE remains its own verified server-backed section (unchanged 096 seam, read-only
