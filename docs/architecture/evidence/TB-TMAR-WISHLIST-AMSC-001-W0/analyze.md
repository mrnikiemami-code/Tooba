## 10. API result / error mapping findings

**`CANONICAL`** on the endpoint path with one residual raw fault.

- Endpoints use `ApiResponseFactory` only (`api.From(result)`, `api.Created(...)`,
  `api.FromFailure(new SemanticError(WishlistErrorCodes.SessionRequired))`). No `Results.Json`,
  no `Results.BadRequest`, no `Results.Problem`, no local `ProblemDetails`, no `catch`-and-map.
- `WishlistOperation.ExecuteAsync` maps typed `SemanticException` to `Result` by stable code. The
  Domain aggregate and the Infrastructure directory throw typed `SemanticException(new SemanticError(WishlistErrorCodes.*))`
  — classification is **by typed code only**; zero `.Message.Contains/StartsWith/==` sites anywhere.
- **Defect F1 (raw fault literal)** — exactly one raw literal remains:
  `Tooba.Wishlist.Infrastructure/Persistence/WishlistOutboxRegistration.cs`:
  `throw new InvalidOperationException("Wishlist integration event is not registered.")`.
  This carries the machine identity in prose `Message` instead of a typed code and has no declared
  code / descriptor / resource. It is a `STRONG_RAW_FAULT` residual (W1 blocker B2).
- Declared-code guard (`KnownCodes` + `IsKnown(string?)`) is **absent** — the module has no
  `ContractOperationException` seam at all (no `using Tooba.BuildingBlocks` typed-fault arm), so it
  cannot yet classify a typed `ContractOperationException` by code.
