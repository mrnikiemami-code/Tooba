## Findings requiring W1 repair (migration plan)

1. **Stable-code ownership relocation (Contracts boundary)**. Move the 27 declared stable codes from `Tooba.Payment.Application/Errors/PaymentErrorCodes.cs` to `Tooba.Payment.Contracts/Errors/PaymentErrorCodes.cs` (`namespace Tooba.Payment.Contracts.Errors`) and add the certified `KnownCodes` HashSet + `public static bool IsKnown(string? code)`. Update all consumers (`Application` ×17 usings, `Endpoints/Errors` contributor, `Host.Tests` ×4 file-path reads + `PaymentArchitectureGuardTests` path pins). No code value changes.

2. **Canonical typed-fault seam**. Add `Tooba.Payment.Application/Composition/PaymentOperation.cs` mirroring the accepted Media/Inventory/Notification/OperatorProfile/PageComposition/Party shape exactly: `ExecuteAsync<T>(Func<Task<T>>)`, value-less `ExecuteAsync(Func<Task>)`, `ArgumentNullException.ThrowIfNull`, `catch (ContractOperationException ex) when (PaymentErrorCodes.IsKnown(ex.Code))` → `Result.Failure<T>(new SemanticError(ex.Code))`, `catch (SemanticException ex)` → `Result.Failure<T>(ex.Error)`; unknown codes and unknown exceptions propagate untouched to the canonical global exception boundary. Classification by typed code only — never by message/prose.

3. **Retire the legacy parallel mapper**. `PaymentExceptionMapper` is a second fault-mapping mechanism with a `PublicAliases` dictionary that **silently rewrites** four wire codes (`payment.not_found` → `payment.missing`, `payment.tracking_reference.required` → `payment.tracking.required`, `payment.unpaid.retry.invalid_state` → `payment.unpaid.retry.invalid`, `inventory.supply.unavailable` → `payment.unpaid.supply_unavailable`) and a `TryMapExact(string? message, out ...)` overload that classifies `InvalidOperationException.Message`. W1 removes it and repoints its 15 call sites (13 handler/query leaf files + 2 orchestrator sites) to `PaymentOperation.ExecuteAsync`. Behavior-preservation decision: the four legacy aliases are **already-canonical declared codes after W1** (`payment.not_found`, `payment.tracking_reference.required`, `payment.unpaid.retry.invalid_state`, `inventory.supply.unavailable` become real `PaymentErrorCodes` members), so the mapping result is identical for every alias while the alias-rewriting mechanism itself disappears. The 11 domain/infrastructure throw sites currently emitting the *pre-alias* wire literals are repointed to the declared constants in the same wave (same string values, so no behavior change).

4. **Missing localization surface**. Add `Tooba.Payment.Contracts/Errors/PaymentErrorResourceSet.cs` (`IErrorResourceSet` owning the `payment.` and `admin.payment.` keyspaces, mirroring `PartyErrorResourceSet`) + `Tooba.Payment.Contracts/Resources/PaymentErrors.resx` and `PaymentErrors.fa.resx` with a bilingual entry for every registered Payment-owned code; register the set in `PaymentEndpointModule.AddPaymentEndpointPresentation()`. Durable guard asserts every registered descriptor key resolves in `en` **and** `fa` through the composed `ResourceErrorMessageLocalizer` (Foundation + Order + Payment sets), so the migration from the Order-owned `payment.*` keys to Payment-owned keys cannot silently regress.

5. **No logging, telemetry, correlation, persistence or schema repair required** (verified: zero `Console.WriteLine`/`Debug.WriteLine`, no second `ActivitySource`, no `StartActivity(`, no parallel correlation, no foreign `DbSet`, 0 migrations touched).
