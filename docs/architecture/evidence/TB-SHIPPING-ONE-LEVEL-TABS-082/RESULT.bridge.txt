Fulfillment now owns an additive one-level method catalog beside the existing two-level catalog. New
domain aggregate Tooba.Fulfillment.Domain/Aggregates/ShippingMethod.cs carries: shipping_method_id;
method_code (stable public code); provider_kind (hidden internal metadata — never a second merchant
configuration level); immutable legacy_service_code plus nullable legacy_option_code; sort_order;
is_active; created_at/updated_at. Localized names live in ShippingMethodTranslation. Identity is keyed on
method_code, NEVER on the option UUID: ShippingServiceDirectory.UpdateAsync deletes and re-creates option
rows, so option IDs are unstable, and ShippingMethod.Update therefore exposes only sortOrder + isActive
while code and legacy binding stay immutable.
Uniqueness encodes the architecture: ix_shipping_methods_method_code is unique on method_code (the
aggregate lower-cases, so case-insensitive collision is impossible) and
ux_shipping_methods_legacy_binding is unique on (legacy_service_code, legacy_option_code) WHERE
legacy_option_code IS NOT NULL — the partial predicate is deliberate so a service-level fallback policy
(NULL option) is never treated as, or colliding with, a second sellable method.
Legacy persisted codes are preserved byte-identically: post:standard; post:express (inactive);
tipax:standard; tipax:express; store_courier; in_person; snapp_courier (inactive). A service that owns
option rows does NOT receive a bare-service method row. Existing service and option rows were not
removed, renamed, or rewritten.

DECISION B2 — 32-CHARACTER WIDTH AND CODE SHAPE
ShippingMethod.MaxCodeLength = 32, matching the narrowest known paid column
(checkouts.shipping_method_code varchar(32)). No order/checkout table was widened or altered and no
historical cart/order/shipment code was rewritten. Shape rules (ShippingMethod.TryNormalizeCode, mirrored
by DB CHECK constraints): length 1..32 after trim + lower-case; at most one ':' separator (the legacy
composite form); every segment [a-z0-9_]+. Consequently '-', ' ', '/', '.', '::', leading/trailing ':'
and triple composites are rejected rather than silently rewritten, and Create throws a typed
SemanticException on an invalid code instead of normalizing it into something else. The 32-character
boundary is proven exactly (a 32-char code is accepted, 33 is not; a composite filling the boundary is
accepted, one more character is not).
