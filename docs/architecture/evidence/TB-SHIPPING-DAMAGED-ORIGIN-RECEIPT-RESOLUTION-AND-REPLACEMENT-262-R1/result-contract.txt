## A — public command resumes an INCOMPLETE recorded replacement
Defect: RunDamagedResolutionAsync answered recorded.Snapshot for ANY Recorded intent, so a durable
no-stock decision or a Reserved decision without a live parcel looked like a completed success (fresh
projection then offered nothing, and the UI cleared its retained envelope while the damaged unit was
already committed to the decision).
Repair (Order owns the public command; Fulfillment owns the continuation ladder):
- completed = Status == Fulfilled OR Outcome == Referral -> exact recorded snapshot, zero writes.
- every other Recorded state continues through ResolveDamagedGoodsCoreAsync with the CURRENT actor,
  checkout, fulfillment and source parcel; no second decision, no second reservation, no silent
  success; an absent record still passes the ordinary projection gate.
- stock still unavailable -> typed fulfillment.damage.replacement_unavailable (pending), no parcel,
  no leaked hold; healthy stock arriving -> the SAME occurrence reserves/continues once and returns the
  actual linked parcel; a genuinely gone hold -> typed fulfillment.damage.reservation_conflict.
- ResolvedCancelled stays historical; changed intent/quantity/outcome stays a typed conflict with zero
  writes (fulfillment.damage.resolution_intent_conflict).
Server-owned resumability: OccurrenceKey is exposed on DamagedResolutionSnapshot /
DamagedGoodsResolutionRecord, carried to AdminShipmentView.DamagedResolutions and admin-api.ts, so a
reload with no local hint can continue the EXACT recorded decision (existing dialog, damagedResume
prop, quantity/outcome/occurrence replayed verbatim; the section renames its ONE 44px entry to
«ادامهٔ تعیین تکلیف کالای آسیب‌دیده» and states the durable decision).

## B — a stale cancellation cannot detach the current replacement
DamagedGoodsResolution.RetainStockBeforeDispatch(Guid cancelledShipmentId, DateTimeOffset now) returns
unless ReplacementShipmentId == cancelledShipmentId. Only the FIRST valid pre-dispatch cancellation of
the CURRENT parcel detaches that allocation and advances the parcel attempt once; a replay of the same
cancelled parcel is a no-op; a replay of an OLD parcel after a retry preserves the new link, attempt,
held reservation and quantities. Shipment.CancelPreDispatch keeps its own idempotence and typed
refusals; public actor/ownership/package-lock guards unchanged; NO Inventory release on parcel cancel.
One live parcel per resolution remains enforced by the aggregate link + attempt-scoped dispatch key
unique index (not by hiding UI).

## C — non-expiring order hold from the FIRST durable Inventory commit
DamagedReplacementReservationRequest no longer carries an expiry; InventoryDirectory
.ReserveForDamagedReplacementAsync passes expiresAt:null into the existing atomic ReserveAsync
primitive; IFulfillmentInventoryGateway.ReserveReplacementReservationAsync lost expiresAt; the separate
CommitReservationForPaidOrderAsync post-step is gone. The purpose-bound hold
(damage-replacement:{resolutionId:N}) is therefore non-expiring from its first durable commit and a
crash between reserve and link leaves exactly ONE recoverable hold that the exact-key retry reuses.
ReleaseExpiredHoldsAsync only selects expires_at IS NOT NULL, so active-order stock can never be freed
by a hold timeout. Only an authorized ORDER cancellation may release the unconsumed hold once.
