Schedule semantics - Tooba.Shipping.Domain/Scheduling/ShippingScheduleAvailabilityEvaluator.cs:
  Pure and deterministic over an EXPLICIT instant; it never reads the system clock, so the same request
  always produces the same verdict. ISO weekday (1 Monday .. 7 Sunday), half-open [start, end) local time
  in the schedule's configured IANA zone, option-specific schedule first with the service-level schedule
  as the documented fallback, and a schedule belonging to a DIFFERENT option is never applied.
  No schedule -> NotConfigured (no restriction). Inactive schedule -> InactiveNotEnforced, the documented
  safe meaning: "inactive" is NOT an operational restriction and never means "unavailable". Active
  schedule with the instant inside a window -> Available. Outside every window -> Unavailable with
  shipping.schedule.outside_windows. No instant supplied -> NotEvaluated (never a success-shaped
  "available"). Two active schedules for one identity -> Ambiguous. Unresolvable stored time zone ->
  Ambiguous with timezone_unresolvable (fail-closed). Midnight-crossing windows are rejected by the
  Domain invariant and the UTC-to-local conversion is total, so DST invalid/ambiguous local times cannot
  arise on this path. This is explicitly NOT a promised delivery slot: a guard test proves no
  promise/estimate field exists on the schedule aggregate or on the evaluation result.

PAYMENT SPLIT - A QUOTE FACT, NEVER A TRANSACTION
  Prepaid            -> payable at checkout = freight + packaging; collect on delivery = 0
  CollectOnDelivery  -> payable at checkout = packaging only; collect on delivery = freight
  Packaging is never collectable: the carrier has no packaging contract, so only the freight component
  can move to collect-on-delivery and PackagingPayer stays Checkout in both rows. Shipping states WHO
  owes WHAT and WHEN. It creates no Payment transaction, no ledger entry and no settlement. Order,
  Checkout, Payment and Settlement were not touched.

FAIL-CLOSED MONEY - NEVER A SUCCESS-SHAPED ZERO
  Every money field is decimal?. FreightNotQuoted, PackagingAmbiguous and CurrencyMismatch all leave the
  amounts null with a stable reason code. An unpriced freight is never summed with zero, ambiguous
  packaging is never resolved by picking the first row, and mismatched component currencies are never
  converted or added. A free-freight threshold waiver applies to carrier freight ONLY; the independent
  packaging component survives it. IsOperationallyEligible requires both a quoted price and a satisfied
  schedule constraint, so NotEvaluated and Ambiguous are never eligible.
