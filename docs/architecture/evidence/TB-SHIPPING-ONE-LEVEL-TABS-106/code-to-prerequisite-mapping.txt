C. Why only 'variants' appears
   ProductPublishReadiness.Missing[] is built from the domains that reported a missing/invalid requirement. Exactly
   one domain reported one, and inside it exactly one sub-rule fired (noDefault). The published diagnostic line is
   therefore a single-element list: missing=[variants].

D. The concrete defect (evidence-backed, NOT fixed here)
   CatalogAttributeSchemaDevelopmentSeed creates its variants via catalog.CreateVariantAsync, i.e.
   IProductVariantDirectory.CreateWorkspaceVariantAsync, whose body performs no SetDefault/EnforceSingleDefault
   (verified by source search: SetDefault appears only at ProductVariantDirectory.cs lines 414/419/442/443 inside the
   matrix-apply path, while EnforceSingleDefault is only called at line 447 in that same path). Because publish
   readiness requires noDefault != true, a product whose variants were created only through the direct create path
   can never be published, no matter how correct its axes/values are.
