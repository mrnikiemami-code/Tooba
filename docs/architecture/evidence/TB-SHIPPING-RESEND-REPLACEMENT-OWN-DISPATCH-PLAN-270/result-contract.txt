ROOT (source-verified at 8e9f42cf7)
A resend or healthy-stock replacement is a new physical attempt. `AdminFulfillmentWorkUnitProjection.BuildParcelRow`
(203-208) gives every `ResendOfShipmentId != null` parcel `plans = []`, so `AdminFulfillmentDispatchTimingAuthority.Classify`
returns `Unspecified` with no handoff/customer date. That is correct: the alternative — `PlansOf(sellerOrderId,
shippingGroupId)` — would lend the shipped parcel's expired promise to a new attempt. The real gap is that no lawful path
exists to give the attempt its own plan.

WHY NO LAWFUL INPUT EXISTS TODAY
The Order-owned accepted evidence stores the plan's outputs (`ShippingGroupAcceptedEvidence.cs:552-610`: handoff
date/open/close/zone, transport working days, policy version, schedule snapshot/revision, preparation start, transfer
departure, handoff deadline, preparation/handoff minutes) but not the carrier/customer/processing WEEK SHAPES. The only
Contracts read that returns those weeks is `IShippingCapturedRevisionQuoteLookup.QuoteAsync`, whose request needs a
`DestinationIdentifiers` plus optional measurement inputs (`ShippingCapturedRevisionQuoteContracts.cs:283-291`) and whose
`Selection` (hence `Settings`/`CarrierWeek`/`ReceivingWeek`/`ProcessingWeek`) is null unless a rate row matched
(`ShippingCapturedRevisionQuoteLookup.cs:680-745`). Order owns neither input any more: `OrderShippingGroup` has no
destination columns (12-79) and the destination ids live only on the seller's CURRENT `CartShippingDraft` (87-96), which
must not be mixed with a historical acceptance; the group's weight/item count were cart facts at submission and were never
persisted. Passing nulls makes weight/count rate modes answer `MeasurementRequired` with no weeks.
