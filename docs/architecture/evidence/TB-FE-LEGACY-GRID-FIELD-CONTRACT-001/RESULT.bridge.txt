Diagnostic: design-system/app-data-grid/legacy-grid-bridge.ts(71,7): error TS2322: Type 'string' is not assignable to type 'ColDefField<T, any>'.
Root-Cause: In the installed AG Grid 36.1.0 types (node_modules/ag-grid-community/dist/types/src/entities/colDef.d.ts:227,250) ColDefField<TData> is a string-literal union of real property paths (NestedFieldPaths), not string. The bridge was assigning a legacy column id into a slot that means "path into the row object", so the type contract encoded a false claim.
STOP-Gate-Decision: PROCEEDED_NOT_BLOCKED - runtime semantics were established from source without speculation. field is not needed by AG Grid in this bridge for column identity or state persistence, sorting keying, filtering, export, data access or row identity.
Evidence-Column-Identity: colId is set explicitly on every data column (legacy-grid-bridge.ts:69) and the installed AG Grid contract comment on ColDef.colId states that the ID is used to identify the column in the API for sorting, filtering etc., defaulting to field only when colId is absent (colDef.d.ts:240-244). Identity and state are therefore colId-based.
Evidence-Sort-Keying: AppDataGrid.onSortChanged reads event.api.getColumnState() and maps colState.colId into the query (AppDataGrid.tsx:352-358), so sort state is keyed by colId, not field.
Evidence-Sort-Order-Source: The adapter is createClientGridQueryAdapter(rows, columns) then executeGridQuery(rows, columns, query) - the app's own engine sorts via the legacy accessor - and AG Grid receives the already-sorted page as rowData.
Evidence-Filtering: Every data column ends as filter: false because the bridge always calls applyAppGridFilterHeader, which returns { ...colDef, filter: false } plus an app-owned headerComponent (app-grid-filter-header.ts:18-33); filtering runs through gridContext.externalFilters. The bridge's own filterMatrix, advancedFilterColumns and externalFilterFields keep using their own field string (legacy-grid-bridge.ts:53-62), which is deliberately not ColDef.field, and applyAppGridFilterHeader's only production caller is this bridge and always passes an explicit spec, so its internal String(colDef.field ?? colDef.colId ?? Evidence-Data-Access-And-Row-Identity: Every data column has a custom cellRenderer to renderLegacyCell which reads col.cell or col.accessor (legacy-grid-bridge.ts:26-32,80), and AgGridReact getRowId is params.data.id (AppDataGrid.tsx:964).
Residual-Role-Analysis: field was only a redundant AG Grid value-service path. For many sortable columns it was already undefined because the id is not a data path - customer (accessor row.customerDisplayName), lines (row.lineCount), amount (row.payableAmount), created (row.createdAt), slug (row.pathLabel), available, credits, debits, reserved (admin-screens.tsx:246-311,489-526 and landing-pages/admin-landing-pages-screen.tsx:316-321). Where the id is a path (title, name, code, status, updatedAt, createdAt, reference, displayOrder) the accessor returns that same property, so AG Grid's secondary sort compared the same values the engine had already sorted by, i.e. a stable re-sort. Removing field makes AG Grid's native sort uniformly value-less while the engine (accessor plus colId) remains the single source of row order, so visible order is unchanged.
