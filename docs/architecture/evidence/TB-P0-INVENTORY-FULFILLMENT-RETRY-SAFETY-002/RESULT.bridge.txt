   so "same reservation" holds — but nothing attests the consumption EVENT.
 * same fulfillment/shipment: NOT PROVABLE. No consumer identity exists anywhere: no column on
   reservations, no parameter on the port, and ExternalReference is an order-process key shared by
   every line of the order (live: all five member-1 reservations carry the identical
   external_reference order-commit:...:process:...). The Fulfillment flag lives in another database.

 * quantity cannot be deducted twice: REFUTED by code. The deduction is guarded only by stock
   arithmetic (Reserved >= q && OnHand >= q), never by reservation state, and MoveTo throws AFTER the
   statement already committed => a replay can deduct a second time with NO journal trace.

   and a Consumed lookup is indistinguishable from a replay.

rather than add a broad Consumed->success shortcut."
