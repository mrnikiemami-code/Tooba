## 2. Implemented primitive

### Domain (`Tooba.Shipping.Domain/Authoring/ShippingAuthoringRevisionSnapshot.cs`)

- `ShippingAuthoringRevisionSnapshot` — immutable row: `SnapshotId`, trusted owner identity
  (`OwnerKind`/`OwnerTenantId`/`OwnerSellerPartyId`), `DraftId`, `SourceRevision`, `FormatVersion`,
  `CapturedAt`, `Payload`. Private setters only; no update method exists.
- `Capture(draft, now)` builds a **typed** payload from the loaded aggregate and never mutates it.
  `Capture` does **not** touch `Revision`/`UpdatedAt`.
- Typed payload records (explicit, no `Dictionary<string,object>`, no type names): owner, binding
  `ServiceCode`/`OptionCode`, draft id/revision/created/updated, raw `ShippingTypeId`, ordered groups with
  `Order`/`CurrencyCode`, every area identity (`SelectedAreaId`, `NodeKind`, `NodeId`), every rate row with
  **all** bounds (weight/count/merchandise) + `FreightAmount` + `PackagingAmount` + min/max delivery days,
  every group title per language, every translation (`null` description preserved), method settings, and the
  weekly schedule with `TimeZoneId` + 7 days including **remembered closed-day hours** and exact `TimeOnly`
  fractions.
- `ShippingAuthoringRevisionSnapshotCodec` (internal) is the single aggregate↔JSONB boundary: explicit
  records, decimal/`TimeOnly` roundtrip, versioned. Decode rejects unknown `FormatVersion` and malformed
  bodies with `shipping.authoring.revision_snapshot_invalid` — **no catch-to-empty decoder** and no fallback
  to "latest"/"current active".
- Ancestry honesty: the persisted draft stores only the selected node identity (`kind`+`id`), not a path.
  The capture records that stored identity verbatim and performs **no** catalog/geography/language read, so it
  never fabricates provenance.

### Port + adapter

- `IShippingAuthoringDraftDirectory.CaptureRevisionAsync(owner, draftId, expectedRevision, ct)`.
- `ShippingAuthoringDraftDirectory.CaptureRevisionAsync` (existing adapter/registration, no new framework):
  1. one Shipping-owned transaction (the only new transaction member);
  2. root row locked `FOR UPDATE` on the full owner scope (`IS NOT DISTINCT FROM` for null seller/tenant),
     closing the read-graph → recheck → INSERT window;
  3. full graph materialised (regions, areas, rows, titles, translations, settings, schedule+days);
  4. missing/foreign owner → `shipping.authoring.draft_not_found`; stale expected revision →
     `shipping.authoring.draft_revision_conflict`, both **before** any row exists;
  5. same (owner, draft, revision) already captured → the **original row/identity/time/content** is returned,
     with no second write;
  6. otherwise insert one row, one commit.
- Concurrent duplicate insert is caught as the unique violation `ux_authoring_revision_snapshots_owner_revision`
  and resolves to the winner's original row (never a second row, never a fabricated one).
- `SaveAuthoringReplacementAsync` and its caller universe are unchanged.

### Persistence

  `format_version = 1`, non-blank tenant. No FK, no cross-schema join, no outbox/rate/policy mutation.
- Additive migration `20261025094223_AuthoringRevisionSnapshots` (Up: one `CreateTable` + one `CreateIndex`;
