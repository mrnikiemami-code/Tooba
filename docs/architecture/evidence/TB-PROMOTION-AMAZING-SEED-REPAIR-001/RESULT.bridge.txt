REPAIR 2 — campaign-price window coverage is now complete
Before: `covered` only compared the *start* (`x.ValidFrom <= validFrom`), so a row that
covered the start but expired before the required end was treated as covered and the
discount was never restored.
After: `covered` requires full span of the required window via CoversRequiredWindow:
    rowValidFrom <= requiredFrom
    && (requiredTo is null ? rowValidTo is null : rowValidTo is null || rowValidTo >= requiredTo)
Endpoint semantics are the existing Pricing convention (AuthoredPrice.IsEffectiveAt:
`at >= ValidFrom && (ValidTo is null || at < ValidTo)`), i.e. the authored window is
half-open [ValidFrom, ValidTo): start inclusive, end exclusive. Start-inclusive coverage
therefore means `rowValidFrom <= requiredFrom`, end-exclusive coverage means
`rowValidTo >= requiredTo`, and an unbounded required window is satisfied only by an
unbounded row. Scope is unchanged: only rows matching the same OfferId + QualifierKind=
MerchandisingCampaign + QualifierKey=CampaignId are expired/replaced; unrelated prices
are never touched. A fully covering row is left untouched (no Expire, no Create).
