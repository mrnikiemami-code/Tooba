===== 2. AUTH FAILURE PATHS (real HTTP) =====

GET /v1/admin/geography/countries, no credential
  -> 401 {"errorCode":"admin.actor.missing","title":"Administrator identity is not authenticated.", ...}

GET /v1/admin/geography/countries, with X-Tooba-Dev-Actor-User-Id: <provisioned admin actor user id>
  -> 403 {"errorCode":"admin.authorization.denied","title":"Access to manage this store is not permitted.", ...}

GET /v1/admin/shipping-services/iso-061-post/rates, with the dev actor header
  -> 403 admin.authorization.denied

POST /v1/admin/shipping-services/iso-061-post/rates            body without `scope`
  -> 403 admin.authorization.denied
POST /v1/admin/shipping-services/iso-061-post/coverage-grants  body without `scope`
  -> 403 admin.authorization.denied

The 401/403 boundary is fail-closed and correct. However every authorized surface is denied, so the two
missing-scope POSTs could NOT be measured at the validation layer over HTTP (see section 4). The 403 is emitted
before the request reaches the MediatR validation pipeline, so it does NOT contradict the 060 repair; it makes the
repair unmeasurable over HTTP in this environment.
