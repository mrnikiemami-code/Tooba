ROOT CAUSE (isolated by counterfactual API call on the same scratch Host)
  POST /v1/storefront/shipping/projection {cartId, language:fa}                                 -> deliveryDates=0, minimumDeliveryDate=absent, draft=null, selectedMethodCode=absent
  POST .../projection {cartId, language:fa, methodCode:"post:express", تهران}                    -> deliveryDates=7, minimumDeliveryDate=2026-10-19
  POST .../projection {cartId, language:fa, methodCode:"tipax:standard", تهران}                  -> deliveryDates=7, minimumDeliveryDate=2026-10-20
The server only computes the delivery-date horizon when a methodCode is supplied. The TB-131 grouped path
never sends one: refreshProjection() is called with no methodCode on mount, and the grouped per-seller
method click handler only updates local groupMethodBySeller state (and the derived fee rows) without
re-projecting. The legacy single-method picker (whose onSelectMethod DOES call
refreshProjection(..., code, ...)) is intentionally not rendered for grouped carts
(storefront-shipping.tsx: projection.deliveryDates.length === 0 branch + isValid at ~line 343 requiring
Boolean(deliveryDate) && Boolean(deliveryTime)).
