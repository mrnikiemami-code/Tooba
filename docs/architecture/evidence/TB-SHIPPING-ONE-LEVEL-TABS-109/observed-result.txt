MECHANISM (ordering, stated as observation + code position — NOT a fix)
  DevelopmentSchemaMigrator.MigrateOrderedAsync runs, for each module migrator in Order, the
  IModuleSchemaMigrationStep(s) whose AfterOrder equals that migrator's Order (lines 136-144). The Catalog
  post-migration step (CatalogDevelopmentSeed.PostMigration.EnsureAsync) therefore runs right after the CATALOG
  migrator and BEFORE the Party/Offer/Pricing/Inventory/Tax migrators. The Catalog seed calls a cross-module
  sellable enricher (ICatalogAttributeSchemaSellableEnricher) which resolves a seller party, then offers, prices,
  tax classification and stock. On an EMPTY database those schemas do not exist yet, so the cross-module call
  fails with 42P01 on party.parties. In TB-106 this was invisible because the run died one step earlier at the
  variant-default publish refusal.

  bootstrap, no reset/seed, no source change. Not claiming the enricher ordering is a defect — only that it is the
  first barrier after the original blocker on an empty database.
