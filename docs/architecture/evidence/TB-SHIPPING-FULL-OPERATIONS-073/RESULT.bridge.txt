WEIGHT AND COUNT TIER SEMANTICS. Weight is a non-negative long in grams (ShippingWeightUnit.Gram) and item count is a non-negative int meaning shipment items (physical units packed), explicitly NOT cart lines and NOT summed cart Quantity. Both axes are optional per rule. ShippingNumericTier is a half-open interval [Min, Max): Min inclusive, Max exclusive; only the upper bound may be open (Max null means "from Min upward"); Min is always concrete and "up to 2000" is written Min=0. Adjacent half-open intervals do not overlap, so 2000 is priced exactly once. Two declared axes on one rule are an intersection, never a union. Zero is a real measurement: a [0,2000) weight tier matches 0 g and a [0,6) count tier matches 0 items, while a [1,6) count tier deliberately does not. Numeric limits are weight 0..1,000,000,000 grams and count 0..1,000,000 items; reversed, zero-width, negative and oversized ranges are refused in the domain with ShippingErrorCodes.WeightTierInvalid/WeightTierOutOfRange/CountTierInvalid/CountTierOutOfRange and in the admin validator with shipping.validation.tier_min_negative / tier_range_invalid / tier_out_of_range.

DETERMINISTIC PRECEDENCE. Precedence is resolved strictly as option identity, then destination depth, then measurement tier, and never by row order. Option-specific rules beat service-level rules, and a service-level rule is the documented fallback for single-option and no-option services. Inside the winning option identity, the deepest destination level wins (ServiceArea > City > AdministrativeArea > Country). Measurement tiers refine only INSIDE the winning option+destination group, so a weight tier never overrides option identity and never overrides destination depth: a city row prices even when it is conditioned while an area row with a better weight fit loses. Ambiguity is reported rather than resolved: two equally specific unconditioned rows give ScopeConflict/shipping.scope.ambiguous and two conditioned tiers matching one parcel give ConditionConflict/shipping.quote.condition_ambiguous. Missing measurements fail closed: a conditioned rule never matches a request that omitted the axis (MeasurementRequired / shipping.quote.measurement_required), and a measurement outside every declared tier is reported distinctly as ConditionNotMatched / shipping.quote.condition_not_matched. Shipping never derives weight or count from cart subtotal or cart line count. When a group holds one unconditioned base row plus conditioned exception rows, the unconditioned row remains the general rule for measurements no tier declares, which is exactly how the pre-existing 9 rate policies keep working because their tier columns are NULL. Currency equality, the free-shipping threshold and coverage-as-service+destination are all unchanged and were re-proved for tiered rows.
