NULLS NOT DISTINCT IS THE LOAD-BEARING PART: under PostgreSQL's default NULLS DISTINCT the unique index
tolerates any number of same-scope rows that differ only by a NULL level (for example two country-scope
policies for one service), and the engine would then answer ScopeConflict for every request. EF Core
8.0.11 expresses it as HasIndex(...).IsUnique().AreNullsDistinct(false), which emits
Npgsql:NullsDistinct=false into the snapshot and the literal NULLS NOT DISTINCT into the DDL. It requires
PostgreSQL 15+; verified on 17.10 (the same major as the Development container). On an older server the
migration fails loudly instead of silently degrading to a partial constraint.
