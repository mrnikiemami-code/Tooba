## 4. B — seed (minimal, explicit, legacy-derived)

Generated by `seed-generate.ps1` (committed) and applied by `seed-geography.sql` (committed, generated —
not hand-written):

**Transcription, not invention.** The generator parses
`StorefrontIranGeography.Provinces` and takes the 12 province codes, their Persian labels and all 47
city names **verbatim** from that file. Nothing was added: no foreign country, no district, no sub-city
service area, no coverage, no enablement flag.

**Stable ids.** RFC 4122 **UUIDv5** (SHA-1, DNS namespace `6ba7b810-9dad-11d1-80b4-00c04fd430c8`) over
ASCII name strings, e.g. `geography.tooba/IR`, `geography.tooba/IR/area/tehran`,
`geography.tooba/IR/city/tehran/01`; the full mapping is committed as `seed-id-map.txt`. The generator
self-tests against the RFC vector `UUIDv5(DNS, "www.example.com") = 2ed6657d-e927-568b-95e1-2665a8aea6a2`
before emitting anything. *(A first attempt rendered the UUID through `[Guid]::new([byte[]])`, whose
mixed-endian layout moved the version nibble; the self-test is what caught it.)*

**City codes are positional on purpose** (`IR-tehran-01`): the legacy catalogue gives cities **no** code
at all, and a transliteration of Persian names would be a guess, whereas the position is exactly
reproducible from the reviewed legacy list. Codes stay language-independent ASCII (`[A-Za-z0-9_-]`; the
underscore appears only because two province codes are multi-word).

**Scope respected.** Provinces are seeded as **roots** (`parent_administrative_area_id = null`): D10
(administrative-level semantics) is undecided, so no level discriminator and no invented intermediate
node was introduced.

**Labels.** One Persian name row per place, keyed by the **Localization-owned** `fa-IR` language id —
read with a single read-only `SELECT` from `localization.languages` inside the script (Geography never
owns the language list, ADR-036 D9) and fail-loud (`GEO047_LANGUAGE_MISSING`) if absent.

**Idempotent and fail-loud.** Every insert is `WHERE NOT EXISTS` on the natural key; the script raises
`GEO047_AMBIGUOUS_*` if a stable code is already owned by another id, `GEO047_CONFLICTING_*_LABEL` if an
existing label for the same place+language carries different text, and `GEO047_POST_*` if any
post-condition of the reviewed shape fails. Applied inside one transaction.

`log-seed-run1.txt` / `log-seed-run2-idempotent.txt`:

```text
run 1 → countries=1 areas=12 cities=47 service_areas=0 country_names=1 area_names=12 city_names=47
run 2 → identical (0 new rows)  ·  after_rerun: countries=1 areas=12 cities=47 translations=60
```

**Honest note on the probes.** The first verification run contained a probe that asserted the *wrong*
thing (a city with no administrative area, which the schema legitimately allows) and therefore did not
raise — and a probe that does not raise is not rolled back by its `BEGIN … EXCEPTION` block, so that one
row survived. It was detected by the run's own residue query, removed immediately
(`log-probe-cleanup.txt`: `before: probe_rows=1 → DELETE 1 → after: probe_rows=0 cities=47 areas=12`),
and the script now deletes its own probe rows unconditionally and reports residue (V13 = 0). The final
shape is 12 areas / 47 cities, exactly the reviewed data.

## 7. Limitations recorded, not hidden

1. `HostStorefrontAmcR3GuardTests` could **not** be executed: the running Host (PID 37028) holds locks on
   `Tooba.Host/bin/Debug/net8.0`, so building the test project fails with `MSB3027/MSB3021`
   (`log-guard-test.txt`). Redirecting the test output outside the repo makes every test in the class fail
   in 18 ms with `System.InvalidOperationException : Repository root not found` — the guard tests resolve
   the repo root by walking up from the test assembly, so that run is a harness artifact, **not** a
   regression. Neither workaround was "fixed" by restarting the Host, which is forbidden here.
2. `administrative_area_id` on `cities` is nullable by design; this bootstrap does not tighten it and
   records the fact instead (V8).
3. `MigrationRunner apply` remains unusable for a Geography-only step because the CLI has no module
   selector (046). The dev bootstrap therefore used EF scoped to the Geography context.
4. Only the `SingleStore`/`store-alpha` dev tenant was bootstrapped. `tooba_marketplace`,
   `tooba_disabled` and the ad-hoc test databases were deliberately left untouched.
5. The runtime read path (`IGeographyLookup` / `IGeographyLabelLookup`) is still not composed into the
   running Host binary (it started before the 044 composition), so the seeded data is not yet served by
   any endpoint; per D8 the legacy route still serves the constant catalogue.

## 8. Rollback plan (schema-only; not executed)

The entire delta of this task is the `geography` schema, so the precise rollback is one statement:

```sql
drop schema geography cascade;
-- expected after rollback: schemas=33 tables_total=237 history_rows_total=116 geography_schema_exists=0
-- i.e. byte-identical to the recorded pre-state fingerprint of §2
```

Narrower, data-only rollback (keeps the migrated schema, removes the bootstrap rows) — FK-safe order:

```sql
begin;
delete from geography.city_name_translations;
delete from geography.administrative_area_name_translations;
delete from geography.country_name_translations;
delete from geography.cities;
delete from geography.administrative_areas;
delete from geography.countries;
commit;
```

Full fallback if anything outside `geography` is ever suspected: restore the verified dump
`tooba_alpha_pre047.dump` (`sha256 e5036fe7…dad2`) taken before any DDL. Note that EF's `database update 0`
is *not* a complete rollback by itself: it drops the tables but keeps the empty `geography` schema and the
emptied history table (measured in 046), which is why the `drop schema` statement above is the specified one.

## 9. Risk

- **Low residual risk inside the dev tenant.** All writes were confined to the new `geography` schema on a
  backed-up local dev database; consumers prove unchanged by source inspection and by the live GET.
- **The data is deliberately thin**: 12 provinces and their 47 cities, no service areas and **no coverage
  verdicts**. ADR-036 warns that an empty coverage set must never be read as "unrestricted", so nothing may
  switch to the new catalogue until Phase 0b coverage rows exist (Gates G2/G3).
- **Activation is still incomplete**: the running Host has no Geography DI/read composition, so no screen
  can consume this data yet.
