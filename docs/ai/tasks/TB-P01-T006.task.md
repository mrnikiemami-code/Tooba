## Hard rules


## Suggested design (adapt if needed, keep small)

1. BuildingBlocks (no EF/ASP.NET): IDomainEvent, IIntegrationEvent, IDomainEventCollector / IHasDomainEvents composition, EventMetadata (EventId, OccurredAt, EventType, CorrelationId, Version, TenantId?, DeploymentId, Edition)
2. Persistence: OutboxMessage entity (not a shared global table type used as one DB table for all modules—map per module), interceptor/SaveChanges helper that collects domain events, maps only registered translations to integration events, inserts outbox rows same transaction, clears events after successful save
3. IOutboxDispatcherStore with raw SQL FOR UPDATE SKIP LOCKED claim
4. IIntegrationEventPublisher + InProcessIntegrationEventPublisher
5. IIntegrationEventHandler<T>
6. HostedService dispatcher: poll interval, batch size, retry base delay, max attempts from config Tooba:Outbox
7. IOutboxModuleRegistration so PlatformProbe registers without hardcoding probe into generic core except sample DI
8. Inbox seam (interface/docs) if full inbox is too much
9. Sample disposable PlatformProbe domain+integration event + table outbox_messages + EF migration
10. Tests covering the mandatory list: same-tx outbox, rollback leaves no outbox, domain not auto integration, dispatcher publishes, processed flag, retry, dead-letter, concurrent claim, tenant A vs B isolation, marketplace DB, worker tenant from message not Host, publisher has no broker package
