2. Preserve Security Boundary

The fix MUST NOT turn customer tracking into unrestricted order lookup.

Required:

authenticated customer sees only owned Orders

guest customer sees only Orders reachable through the existing supported guest-order access mechanism

arbitrary OrderId/ShipmentId/PackageId guessing must not expose data

cross-customer/cross-store access rejected safely

If the existing 404 is correct for an unauthenticated user with no valid guest proof, keep that behavior.

The repair is to make the REAL supported guest/customer path work, not to make anonymous arbitrary access work.

3. Customer Tracking Projection

For an Order with active Consolidated Package:

Primary customer-facing tracking:

Consolidated Package tracking number/reference

Consolidated Package status

central provider where available

Secondary/detail:

member Seller Shipments may remain visible in expandable detail if current UI supports it

internal/member tracking history preserved

do not overwrite/delete member tracking

For Order without Consolidated Package:

existing Seller Shipment tracking behavior remains unchanged

For Cancelled pre-dispatch Consolidated Package:

do not present cancelled central tracking as active primary tracking

fall back to current eligible shipment state/tracking

4. Status Preference Rules

Customer projection must be deterministic.

Suggested hierarchy:

Active Dispatched/Delivered Consolidated Package -> central tracking primary

Active Created/Ready Consolidated Package -> central package shown as preparing/ready if current customer UX exposes pre-dispatch tracking state

Cancelled Consolidated Package -> not primary

No active Consolidated Package -> existing member Shipment tracking projection

Do not hide historical member Shipment records.
