3. Locked Business Policy
Cart

Cart is a shopping intent container.

Adding/updating an item in Cart:

DOES NOT create a hard Inventory reservation

DOES perform authoritative availability validation

may keep item in Cart even if later inventory changes, with later revalidation

Cart persistence/lifetime is independent from Inventory hold lifetime

Checkout before Order commit

Cart/Shipping pages:

revalidate stock as required

DO NOT create long-lived hard reservation merely because page is opened

no hidden reservation polling/refresh loops

Order/Payment Commit Boundary

Hard reservation begins only when the customer performs the final commit action that creates/commits the Order and begins the payment phase.

Use the existing checkout architecture boundary if possible.
Do not invent an extra intermediate Order.

The operation must be atomic enough that:

Order cannot be committed as payable if supply guarantee fails

no orphan reservation remains if Order commit fails

no Order duplicate on retry
