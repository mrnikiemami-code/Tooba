12. Cart Finalization Semantics — CRITICAL

Define one canonical backend operation/state for completed checkout cart finalization.

Clear/finalize cart when:

manual/card-to-card customer proof successfully submitted and Order is now waiting for Admin confirmation

Do NOT incorrectly clear retry context when:

online payment initiation fails before a valid Order/payment attempt

online sandbox payment returns Failed and user must retry, unless current committed-Order architecture already considers the original Cart consumed; in that case UI must switch to Order payment retry and never create a second cart/order

The key invariant:
After Order has been committed, retry payment must operate on that Order/Payment, not create another Order from the same cart.

Required:

no duplicate Order after refresh/back/retry

header/mini-cart reflect correct finalized state

old completed cart cannot be reused to submit a second Order

Document exact current model chosen.
