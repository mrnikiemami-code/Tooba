3. Ownership Rule — LOCKED

Once Order/Payment exists, Payment result/status ownership MUST NOT depend on the mutable active Cart.

Authenticated

Authorize Payment against current authenticated customer/session and the Payment/Order owner.

Guest

Authorize with the existing stable committed checkout/order/payment guest proof.

Forbidden:

new empty Cart authorizing old Payment;

arbitrary cartId;

dev actor;

paymentId alone.

If the original guest proof is currently stored with Cart session, retain only the minimal committed-order/payment proof before replacing the active Cart.

4. Polling State Machine

Replace unconditional 20-second polling with explicit state-aware polling.

Poll only while a status can legitimately change asynchronously, e.g.:

Pending / Processing / Verifying -> poll.

Stop immediately for:

AwaitingAdmin / manual Pending awaiting human confirmation;

Succeeded;

Failed;

Rejected;

Cancelled;

any other terminal/stable result state.

For manual AwaitingAdmin:

show در انتظار تایید;

DO NOT poll every 1.5s waiting for an Admin who may act minutes/hours later;

customer can refresh/reopen Order later.

Also stop timer on:

unmount;

route change;

ownership/auth failure.

No overlapping requests.
