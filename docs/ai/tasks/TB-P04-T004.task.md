Workspace Philosophy

A Workspace is:

task-oriented
context-rich
multi-domain
operational
stateful
professional

It is NOT a page per database table or a menu mirror of backend modules.

A future Product Workspace may compose:

Core product info
Category / Brand
Attributes
Variants
Media
Offer / Seller context
Pricing
Tax classification
Inventory
SEO
Content
Publication
Audit/history

without separate CRUD menus for each backend module.

Workspace Shell

Support:

title
subtitle/context
status
primary/secondary actions
breadcrumbs
section navigation
main content
optional side panel
optional inspector

Must work in RTL/LTR and desktop/tablet/mobile.

Action Hierarchy

Support:

Primary action
Secondary actions
Destructive action
Overflow actions
Contextual actions

Actions need loading, permission-disabled, business-state-disabled, and confirmation states.

Navigation Pattern

Generic workspace navigation must support:

tabs
side navigation
responsive compact navigation
deep-linkable sections

Do not hard-code Product-specific sections into primitives.

Summary + Detail

Support:

high-value summary
→ primary working area
→ contextual inspector/side panel

Editable Sections

Create consistent patterns for:

view mode
edit mode
save
cancel
validation
dirty state
optimistic/concurrent conflict
server validation errors
permission denied

Avoid one giant form.

Unsaved Changes

Implement reusable dirty-state tracking:

detect dirty section
prevent accidental navigation loss
discard
save
multi-section support

Conflict UX

Create foundation for:

record changed by another actor
stale version
optimistic concurrency failure

Surface reload/review/retry. Never silently overwrite.

Permission State

Support:

can view
can edit
can execute action
read-only
partially hidden sections

Generic components must not call SpiceDB directly.

Activity / Audit

Reusable presentation for:

business activity
audit history
status transitions
actor
timestamp
metadata

Keep:

Technical Log != Business Audit != Security Audit

Inspector / Side Panel

Support contextual:

metadata
related entities
quick actions
warnings
validation details
history snippet

On mobile, side panel may become Drawer/Sheet.

Status / Health Strip

Support generic semantic status items for publication, availability, payment, fulfillment, verification, warnings, and blockers without embedding domain logic.

Workspace + Data Grid

Define patterns:

list → select row → open workspace
workspace → embedded related-data grid
workspace → related-grid bulk action
workspace → preserve saved view when returning

No domain API integration yet.

Master-Detail

Provide reusable list/grid → workspace foundation with:

deep links
back-to-list state preservation
selected-row context
mobile navigation

Prefer adapters over direct Next router coupling.

Async Command State

Standardize:

idle
confirming
submitting
succeeded
failed
conflicted

Destructive Actions

Reusable confirmation pattern with clear consequence, optional typed confirmation for high-risk actions, permission/business-state gating, loading, and failure recovery.

Empty / First-Use States

Distinguish:

no data yet
no permission
not found
filtered empty
not configured
temporarily unavailable

Mobile Workspace

Define credible mobile patterns:

compact header
section switcher
sticky primary action
side panel → drawer
activity timeline
related grids → mobile card renderer

Do not merely shrink desktop.

Accessibility

landmarks
heading hierarchy
keyboard section navigation
focus management after actions
announced validation/errors
status changes
dialog/drawer focus
touch targets
reduced motion

Internationalization

Provide message seam for save/cancel/edit/retry/reload/discard/unsaved/permission/conflict/not-found/history/details/more-actions.
