Inventory Module

Create dedicated Inventory with Domain / Application / Infrastructure.

Inventory owns InventoryDbContext, inventory schema, migrations, write model.

No foreign DbContext/repository access. No cross-module FK.

Inventory Target

Primary commercial target is OfferId (seller-specific Marketplace stock). Retain CatalogVariantId as descriptive lookup copied via Offer gateway.

Do not add stock fields to Offer or Product.

Warehouse / Location

Minimal InventoryLocationId, Code, Name, Status, CreatedAt, UpdatedAt.

Stock Record

StockItemId, OfferId, CatalogVariantId, LocationId, OnHand, Reserved, timestamps.

Available = OnHand - Reserved (not independently persisted).

Integer quantity. No float. Reject OnHand < 0, Reserved < 0, Reserved > OnHand.

Adjustments with reason, timestamp, idempotency seam.

Reservations: reserve / release / consume, concurrency-safe, durable ReservationId, external reference seam without Cart/Order types.

Concurrency: atomic PostgreSQL UPDATE so two concurrent last-unit reserves cannot both succeed.

Availability contract IInventoryAvailabilityGateway. Price/active Offer does not imply stock.

Validate Offer via IOfferLookupGateway. Optional Variant via ICatalogLookupGateway. No Offer/Catalog DbContext.

Multi-location supported. Two sellers / two Offers on same Variant hold independent stock.

Marketplace vs Single-Store: same abstraction; tenant-aware persistence; no Host parsing.

Events via existing outbox:

inventory.adjusted.v1
inventory.reserved.v1
inventory.released.v1
inventory.reservation_consumed.v1
inventory.availability_changed.v1

No MassTransit/Authzed types in Domain/Application.

Tests must cover listed invariants, PostgreSQL Testcontainers, PostgresSerial, Failed=0 Skipped=0.

Persian documentation mandatory. CS1591 green.
