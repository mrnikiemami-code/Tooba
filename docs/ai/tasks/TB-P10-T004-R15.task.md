Title:
Reservation Cycle Foundation — Auditable Initial/Retry Holds with Immutable History and Policy Limits

Architect Intent

Implement the locked reservation policy as a foundation only.

Core rules:

Hard reservation begins at committed Order/payment entry, never at AddToCart.

Payment Attempt != Reservation Cycle.

Failed attempts inside an active cycle never reset/extend reservation time.

A new cycle starts only after the previous cycle ended and Inventory successfully reacquires stock.

Released/Expired reservations are never resurrected.

Every cycle is immutable/auditable.

Initial and retry cycles may use different TTLs.

Max reservation cycles is policy-driven.

Same Order is retained across retries.

Server ExpiresAt is authoritative; frontend countdown later is presentation only.

4. Immutable History
