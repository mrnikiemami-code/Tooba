Title:
Store Preview Variant-Fidelity Repair — Fill Missing Store Slots with Preview-Only Fake Data

Architect Decision

R7 correctly enforced Store/Sample source isolation and introduced preview-only placeholders.

User visual inspection shows the remaining UX defect:

Generic placeholder boxes do NOT preserve the true visual geometry of the actual Section Variant. The user cannot reliably understand how the Home template will look once real Store data exists.

Therefore Store Preview must render the SAME real Section Variant even when Store data is missing or insufficient.

The repair is:

Store Preview
→ read real Store data only
→ if data is missing/insufficient for the selected Variant
→ fill ONLY the missing visual slots with preview-only fake data
→ render the SAME production Section/Variant component

No Template/Sample Catalog data is allowed to leak into Store mode.
No fake preview record may persist.
No fake preview record may render on the published Storefront.

Do NOT expand other industries.
Do NOT implement cloning.
Do NOT create TB-P10-T023.

3. Preview Fill Contract

Introduce one centralized preview-only fill policy.

Conceptually:

PreviewFillPolicy

receives SectionType

receives VariantKey

receives required/preferred visible item count

receives actual Store items

returns:

all real items

plus only the number of preview-only fake items required to make the Variant visually understandable

Rules:

if Store data is sufficient: use only Store data

if Store data is partially sufficient: keep Store data and fill missing visual slots

if Store data is zero: fill all preview visual slots with fake preview items

never fetch Template Catalog content as fallback in Store mode

This policy must be centralized, not scattered magic counts.

4. Variant Contract Is Source of Truth

The selected Variant determines its visible preview needs.

Product FeaturedPlusRail → 1 featured + rail items

Reviews CardCarousel → intended visible review cards

Use current Variant registry/responsive contracts wherever possible.
