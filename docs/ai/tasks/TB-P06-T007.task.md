Locked session architecture (updated):

Host API = Bearer opaque SessionId (Guid), server-side session store
Browser clients = Next.js BFF with HttpOnly cookies (`tooba_session`, `tooba_refresh`)
BFF injects `Authorization: Bearer {SessionId}` server-side to Host
CSRF = double-submit (`tooba_csrf` cookie + `X-Tooba-Csrf` header) on mutating BFF routes
Production OTP = provider-backed fail-closed unless `Identity:OtpDelivery:Mode=Webhook` configured
No localStorage session tokens in customer/storefront auth paths

Objective

1. Replace monolithic OTP sender with `IOtpDeliveryProvider` + `OtpDeliveryProviderSender` adapter.
2. Add Next.js BFF auth routes: `/api/auth/login|logout|refresh|me|csrf`.
3. Add `/api/customer/[...path]` proxy with server-side Bearer injection.
4. Remove localStorage session auth from customer-api, wishlist-api, profile, address, storefront review/Q&A.
5. Add tests: `OtpDeliveryProviderTests`, `csrf.test.ts`, updated customer tests for `/api/customer` paths.

Do NOT change Shopeiva UI files.
Do NOT redesign Identity domain semantics.
Do NOT expose refresh/session tokens to JavaScript.
