# A. Core Separation

Define:

```text
Cart
Checkout
Order
Cart line
Checkout session
Order line
Order commercial state
Payment state
Fulfillment state
```

Hard rules:

```text
Cart != Checkout != Order
Cart != live Price Book
Cart != Inventory ATS write-model
Checkout != Payment PSP internals
Order snapshot != live Catalog / Offer / Price / Inventory
Order commercial state != Payment state != Fulfillment state
```

**Cart** = pre-order commercial session (lines, selected context).

**Checkout** = capture process (revalidation, reservation, payment initiation, placement attempt).

**Order** = confirmed commercial record with snapshots.

No module may treat these as one table with a status flag as the whole design.

Must not own as SoT: product titles as live catalog copy, live stock counts, PSP secrets, shipment tracking.

---

# B. Cart Ownership

Cart owns cart lines and session commercial context:

```text
sellable / offer refs
quantity
selected market / currency / channel
optional identity / party
applied promotion refs (codes/ids, not promotion definitions)
```

Cart does not own live price books, stock, or catalog copy.

No Cart schema in this task.

---

# C. Guest Cart

Guest cart is allowed (T007). Identified by opaque cart/session id, not login.

Merge policy after login:

```text
NEEDS_LATER_P00_DETAIL
```

Must not invent silent overwrite of an authenticated cart.

Guest is not Identity. Guest token is not SpiceDB skip.

---

# D. Authenticated Cart

Bound to Identity; may link Buyer Party.

Actor != Buyer still applies if B2B later (T007). Identity is not the commercial buyer by default.

Do not require login to hold a cart. Do not store Party tables inside Cart.

---

# E. Marketplace Multi-Seller Cart

One cart may contain lines from multiple sellers.

Partition by seller/offer for reservation, fulfillment grouping, and payment policy later.

Do not force one-seller carts unless product later decides.

Seller A lines must not consume Seller B stock or money.

---

# F. Single-Store Cart

Same Cart module. One implicit seller is allowed.

UX need not show seller. Do not collapse Cart into Catalog Product. Do not scatter `if (isMarketplace)` as the cart model.

---

# G. Cart Line Validity

Lines reference Offer/Variant (sellable) ids.

Stale catalog/offer (ended, unpublished, ineligible) fails at revalidation, not by joining Catalog tables from Cart.

Cart is not Catalog. Offer bind is a reference, not owned copy as write-model truth.

---

# H. Cart Pricing

Cart **displays** quotes via Pricing contract (T009).

Cart does not author prices. Stale display ≠ charge amount.

Checkout must re-quote. Search/PLP display price is not Cart truth.

No Pricing schema in this task.

---

# I. Cart Inventory

Optional reservation per T010 timing policy.

Cart does not store ATS as truth. Cart does not join Inventory tables.

Reservation remains Inventory-owned (T010). Cart may request hold via contract.

No Inventory schema in this task.

---

# J. Checkout Responsibility

Checkout owns the process:

```text
revalidate price / availability / eligibility
ensure reservations
collect addresses
start payment
place order OR fail closed and compensate
```

Checkout is not a renamed Cart. Checkout is not Order history.

No Checkout schema in this task.

---

# K. Checkout Session

Distinct from Cart. Created from a cart snapshot/version.

Concurrent checkouts: idempotency keys.

Cart may remain until success policy.

Exact cart-clear-on-success policy:

```text
NEEDS_LATER_P00_DETAIL
```

---

# L. Checkout Revalidation Pipeline

Conceptual steps (not an implemented orchestrator):

```text
resolve tenant
lock / version cart
re-quote (Pricing)
re-check availability (Inventory)
re-check offer / market eligibility
re-check authz (SpiceDB) where needed
apply promotions (as quote modifiers)
compute payable
```

Any fail → no successful sellable Order (or no capture) per failure matrix (AM).

Do not skip Inventory because a Search in-stock badge was true (T010).

Do not skip Pricing because Cart displayed an amount (T009).

---

# M. Order Placement Boundary

Order is created only after Checkout decides confirm policy (see U).

Command: PlaceOrder. Event: OrderPlaced.

Cart/Checkout do not remain the long-term commercial SoT after a confirmed Order.

No Order schema in this task.

---

# N. Order Ownership

Order owns confirmed header/lines **snapshots**, plus refs:

```text
buyer / actor / payer refs
market / channel / currency
totals
quote / version refs
payment refs (not PSP internals)
fulfillment refs (not live stock, not shipment tracking as SoT)
```

Order does not own live ATS. Order does not own Price Books. Order does not own Catalog.

---

# O. Order Snapshot Policy

Snapshot at least:

```text
product title / SKU as sold
offer id / sellable id
seller partition
unit / extended amounts
tax / fee as quoted
applied promotions
FX snapshot if conversion used
addresses
quote id / version
```

Later catalog, offer, price, membership, or inventory mutations must not rewrite Order history.

Align with T009 Order commercial snapshot and T010 ordered-quantity snapshot vs live stock.

---

# P. Order Line

Line = sellable + qty + commercial snapshot + seller/offer partition.

Not a live Catalog row. Not a live Inventory row. Not a live quote that mutates in place.

---

# Q. Order Status vs Payment/Fulfillment Status

Separate:

```text
Order commercial state
Payment state
Fulfillment state
```

Do not collapse to one `Status` that means paid-and-shipped.

A placed Order may exist with failed payment per policy U; do not invent that as silent paid.

---

# S. Fulfillment Grouping

Fulfillment units derived from partitions/locations via contract after Order exists.

Order does not ship. Fulfillment does not write Order commercial snapshots as live catalog.

Do not design Fulfillment in this task.

Align with T010: shipping a unit commits/decrements via Inventory contracts/events.

# V. Failure / Compensation

On fail:

Payment failure / timeout must not leave orphan Inventory reservations (T010).

Promotion module owns definitions. Do not store “sale price” as Cart or Catalog truth.

# Y. Address Model

Checkout collects shipping/billing.

Order **snapshots** addresses.

Party address book is current facts, not historical Order truth (T007).

Do not join Party address tables from Order as history.

# Z. Market / Locale / Currency

Cart/Checkout carry Market and Currency from context (T009).

Locale != Market != Currency. Domain is not Currency.

# AA. Sales Channel

Not Identity. Not Locale. Not Host parse inside Cart/Checkout/Order.

# AB. B2B Approval Readiness

Checkout may later pause in Request-to-Buy before PlaceOrder.

Actor vs Buyer Party preserved on Order (T007).

Approval-to-buy does not rewrite price books (T009).

Do not implement B2B checkout now.

# AC. Request-to-Buy vs Online Purchase

Same Order module; different process.

Do not fork Order schema into “B2BOrder”.

---

# AD. Cancellation

Order-owned cancellation policy + inventory release + payment void/refund commands.

Eligibility is a business rule after SpiceDB check (T006).

Do not cancel by deleting Order history. Do not implement cancellation workflows now.

# AF. Customer / Seller / Admin Views

Seller sees own partition. Customer sees own order. Admin composed read models.

No mega-joins. No cross-module table joins (T004).

At minimum recommend for ADR:

1. Cart != Checkout != Order; not one status-flag table as the design.
2. Guest cart allowed; identified by opaque cart/session id, not login.
3. Authenticated cart may bind Identity and Buyer Party; Actor != Buyer remains.
4. Marketplace multi-seller cart is partitionable; Seller A cannot consume Seller B money or stock.
5. Single-Store keeps the same Cart/Checkout/Order modules; implicit seller does not merge them into Product.
6. Checkout revalidates Pricing quote and Inventory availability; display/search is not sell permission.
7. Order owns historical commercial snapshots; later catalog/price/inventory mutations do not rewrite history.
8. Order commercial state != Payment state != Fulfillment state.
9. Idempotent placement; duplicate submit does not duplicate orders.
10. Compensation releases reservations and payment attempts; fail closed on the sell path.
11. Addresses are snapshotted on Order; Party address book is not Order history.
12. B2B approval / request-to-buy is a process overlay, not a second Order product.
13. Views via projections; no cross-module joins.
14. Payment is commanded via contract; PSP internals are not Cart/Checkout/Order SoT.
15. Prefer Order (or OrderIntent) id before capture so payment is not orphaned; exact sequence later.
