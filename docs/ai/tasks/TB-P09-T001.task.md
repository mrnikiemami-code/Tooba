5. Locked Business Rule — Settlement Does NOT End Return Rights

Seller Settlement and Customer Return are independent lifecycles.

A completed Seller settlement MUST NOT automatically make an otherwise valid customer return ineligible.

If a valid return occurs AFTER seller settlement:

keep the completed settlement immutable

do NOT delete/rewrite the old settlement

create/reuse a seller financial adjustment / seller receivable / debit entry

deduct that amount from future payable settlement(s)

if no future payable amount exists, preserve the seller negative balance/receivable according to existing Finance design

future seller payouts must account for the adjustment

audit trail must remain complete

If seller has NOT yet been settled:

current unpaid/payable seller amount should reflect the return/refund using existing Finance rules

do not pay out money that has become non-payable

Do NOT invent a second ledger if Finance already has adjustment/receivable semantics.

6. Return Window Finality

There MUST be a point after which return is no longer allowed.

That point comes from Return eligibility/policy, NOT seller settlement.

Examples:

return window expired

item non-returnable

already fully returned/refunded

lifecycle no longer allows return

policy-specific rejection

When eligible=false:

UI hides/disables return operation appropriately

backend rejects direct calls
