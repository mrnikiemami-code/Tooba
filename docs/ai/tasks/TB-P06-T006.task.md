Locked authentication architecture:

Bearer token = opaque SessionId (Guid), NOT JWT
No secure auth cookies; session state server-side
Refresh token = separate opaque secret in JSON body
CSRF protection N/A for Bearer-only API (document, do not add cookies)
Tenant/Edition from resolved session, never from client spoof headers/body

Objective

Establish a production-grade authentication and HTTP security baseline covering:

CORS policy for auth and health surfaces
auth-sensitive rate limiting (429 enumeration-safe)
security response headers (non-breaking for Shopeiva)
request body size limits
forwarded-headers / trusted proxy integration for rate-limit IP keys
Production OTP fail-closed (no silent in-memory capture)
auth observability without secret leakage
integration test proof

Do NOT add cookie-based sessions.
Do NOT add CSRF tokens for Bearer-only flows.
Do NOT redesign Identity domain semantics.
Do NOT add UI scope.

D — Rate Limit Policy

Auth-sensitive operations throttled per IP+operation sliding window:

login
refresh
password_reset_request
password_reset_complete
identifier_verification_request
identifier_verification_complete

Exceeded limit => HTTP 429 + `identity.rate_limited` (enumeration-safe).

Configurable via `AuthRateLimitPermitLimit` / `AuthRateLimitWindowSeconds`.

Create:
docs/evidence/TB-P06-T006/04-rate-limit-policy.md

E — CORS Policy

Named policy `ToobaCors` from `CorsAllowedOrigins`.

Empty origins => deny all cross-origin (same-origin / reverse-proxy default).

Wildcard `*` forbidden at validation.

Apply `RequireCors("ToobaCors")` on `/v1/auth` group and health/live + /health when CORS enabled.

docs/evidence/TB-P06-T006/05-cors-policy.md

F — CSRF and Session Model

Document locked Bearer-only model:

Authorization: Bearer {SessionId}
No auth cookies issued by Host
CSRF not applicable to Bearer header API clients
RejectUntrustedTenant blocks tenant spoof via headers/body/query/cookies

Do NOT implement cookie sessions or antiforgery tokens.
