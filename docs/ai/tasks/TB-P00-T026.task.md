# A. Core Separation

Hard rules:

```text
Return != Cancellation
Return != Refund
Return != Fulfillment
Return != Inventory
Return != Order
```

Order owns commercial order truth.

Fulfillment owns delivery/shipment execution truth.

Payment owns refund/payment execution truth.

Inventory owns stock/restock authority.

Returns/RMA owns return request, eligibility, lifecycle, inspection/disposition coordination.

---

# B. Scope

Returns/RMA should conceptually cover:

```text
Return Request

Return Item / Quantity
Return Reason
Eligibility
Approval
Reverse Logistics
Received/Inspected
Disposition
Refund Request/Instruction
Restock/Disposition Instruction
Resolution
```

Do not create schema.

---

# C. Cancellation vs Return

Hard rule:

```text
Cancellation = before/without completed delivery lifecycle
Return = after fulfillment/delivery or after dispatch according to policy
```

Do not represent both with one boolean/status.

Exact boundary by product policy may vary, but concepts remain distinct.

---


# BB. Decision Summary

Classify:

```text
RECOMMENDED_FOR_ADR
NEEDS_LATER_P00_DETAIL
DEFERRED
```

At minimum recommend:

1. Returns/RMA is separate from Order, Fulfillment, Payment and Inventory.
2. Cancellation and Return are distinct lifecycles.
3. One Order can have multiple partial RMAs.
4. Returnable quantity is concurrency-safe and quantity-aware.
5. Marketplace seller responsibility is explicit and isolated.
6. Order/Fulfillment evidence is consumed via contracts, never joins.
7. Return received does not automatically mean Inventory restock.
8. Refund execution belongs to Payment.
9. Return approval does not equal refund completion.
10. Promotion/price historical allocations are reused; current pricing rules are not re-run blindly.
11. Tax refund behavior is an explicit future Tax policy hook.
12. Reverse logistics provider is behind adapter.
13. Inspection and disposition are separate from refund state.
14. Exchange is not collapsed into Return and remains deferred.
15. Customer/seller/admin actions are SpiceDB-authorized.
16. Critical actions are idempotent and audited.
17. Reconciliation is first-class across Return/Payment/Inventory/Fulfillment.
18. Returns UI is a case/workflow/timeline experience, not CRUD.
19. Private RMA flows are excluded from public SEO/Search.
20. Analytics/Fraud/Notifications consume facts/signals but do not own RMA truth.
21. Backend/module boundary != UI boundary.
22. UI implementation requires visual evidence and Architect visual acceptance.

Do not create final ADR yet.
