Locked Product/Architecture Decisions

These are now product rules and must not be lost in later tasks:

Customer Order is the customer-facing aggregate summary.

Operational fulfillment is NOT one whole-order state.

Operational hierarchy must support:

Order

Seller Order / seller-owned operational group

Shipment

Order Line + Quantity allocation

One Order may contain multiple sellers.

One seller-owned order/group may produce multiple Shipments.

One Shipment has exactly one shipping method/provider.

Different Shipments within the same customer Order may use different shipping methods.

Operations must support BOTH:

fast whole-group / whole-shipment actions

partial selected-line / selected-quantity actions

Whole-group actions and partial actions MUST reuse the same backend command/domain logic; no duplicate business rules.

Return/Refund is line + quantity aware.

Return policy is snapshotted on Order Line at purchase time.

Return and Refund are distinct:

Return = مرجوعی

Refund = بازگشت وجه
