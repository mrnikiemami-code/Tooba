Core Principle

Backend/module boundaries must NOT dictate visual/UI boundaries.

The Design System must support composed experiences such as Product / Order / Seller / Customer / Content / Tenant Settings / Return Case workspaces without one UI package per backend module.

Design System Structure

Create a clear frontend-owned Design System structure (tokens, primitives, patterns). Exact paths may follow current frontend convention (`src/frontend/design-system/`). Avoid a monolithic components dump.

Token Foundation

Define semantic token layers: color, typography, spacing, radius, shadow/elevation, border, z-index, motion, breakpoint/layout, density.

Separate raw/reference values from semantic product tokens.

raw red != danger
raw gray != muted foreground

Prefer semantic roles: background, surface, surface-elevated, foreground, muted, border, primary, secondary, success, warning, danger, info, focus.

Do not hard-code Shopeiva brand red as universal Tooba semantics.

Theme Model

Support safe runtime theming: design tokens, brand assets, approved variants, layout/composition config, tenant theme config.

Hard rule: no arbitrary executable code from DB.

Do not implement tenant admin theme editor yet.

Prepare a typed theme contract/config model suitable for future tenant resolution.

Light / Dark

Support light and dark using semantic tokens. Do not scatter theme-specific CSS throughout feature components.

RTL / LTR

Bidi-safe from the foundation: RTL, LTR, mixed-language, logical spacing/alignment, direction-sensitive icons, logical drawer/sheet placement.

Prefer logical properties. Do not treat dir=rtl alone as success.

Typography

Production-grade typography for Persian and Latin: family stack, display, headings, body, caption, label, numeric/tabular, weight, line height.

Persian readability is primary. Avoid tiny dashboard typography. Do not ship font files to user-facing artifacts in this task.

Core Primitives

Button, IconButton, Input, Textarea, Select foundation, Checkbox, Radio, Switch, Badge, Tag/Chip, Separator, Card/Surface, Tooltip, Popover foundation, Dialog/Modal, Drawer/Sheet, Tabs, Accordion, Skeleton, Spinner/Progress, Alert, EmptyState, ErrorState.

Do not install a large UI framework that overrides Tooba design ownership.

Form Foundation

Integrate react-hook-form + zod. Patterns: label, description/help, validation error, required/optional, disabled/read-only, loading/submitting, LTR islands for email/phone/code.

Do not implement domain forms yet.

Feedback / Notification

inline validation, Alert, Toast/notification, loading, success, warning, error, empty state, retry state.

If Shopeiva toast dependency was classified REPLACE, do not blindly copy it.

Overlay / Focus Management

Dialog, Drawer, Popover, Tooltip must address keyboard, focus trap/return where appropriate, Escape, SR semantics, scroll lock as applicable, RTL/LTR placement, mobile.

Responsive Foundation

page container, stack, cluster, grid, responsive section, sticky action bar, desktop/mobile shell slots. Mobile-first. Do not encode Storefront-specific layout into low-level primitives.

Commerce Presentation Primitives

Reusable visual primitives only: MoneyDisplay, PricePresentation, DiscountBadge, AvailabilityBadge, StatusBadge, QuantityControl, RatingDisplay, MediaAspectBox, SellerIdentityDisplay.

Hard rules: visual component != business truth. MoneyDisplay does not calculate Pricing. DiscountBadge does not calculate Promotion. AvailabilityBadge does not query Inventory. Components receive already-resolved view data.

Status Semantics

Controlled status presentation: neutral, info, success, warning, danger, pending. Domain mapping belongs in feature/view-model layer.

Icons

Use accepted T001 icon strategy (lucide KEEP). Standardize sizes and icon-only accessible labels. Do not mix multiple icon libraries without justification.

Motion

Restrained motion tokens. Respect prefers-reduced-motion.

Accessibility Baseline

keyboard, visible focus, semantic HTML, labels, aria only where needed, contrast, touch target, disabled semantics, error association, reduced motion.

If no frontend component test harness exists, document that gap and use lint/type/build plus static source checks; do not introduce a heavy test framework solely for this task without strong justification.
