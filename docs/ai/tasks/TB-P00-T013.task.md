# A. Core Separation

Define:

```text
Content
Page Composition
Blog
Catalog
Media
SEO Engine
Search
Theme
```

Hard rules:

```text
Content != Blog
Content != Page Composition
Content != Catalog
Content != Media
Content != SEO Engine
```

**Content** = semantic/editorial knowledge and publishable material (types, items, locale variants, publishing state, revisions, editorial taxonomy, knowledge eligibility).

**Page Composition** = arrangement/configuration of approved sections/components for a page experience (page instances, slots, bound ids, theme region hints).

**Blog** = a content type or presentation pattern, not the root architecture.

Must not own as SoT: product identity, binaries, technical canonical/hreflang/sitemap engine, search index writes as catalog truth, PSP/payment, cart/order.

No module may treat Content as Blog-only, or treat a layout tree as the only content model.

---

# B. Content Capability Scope

Content covers:

```text
Article
Buying Guide
News / Editorial
FAQ
Policy / Help
Brand / Category editorial
Campaign copy
Landing content
Knowledge article
future registered types
```

Do not create a new module or table per page type.

Types are registrations on one Content capability.

Landing **content** is not the landing **layout**.

# F. Versioning / Revisions

Immutable revision history.

Current draft vs published revision.

Rollback, compare, audit.

Do not force event-sourcing as the Content model.

Working copy ≠ live published copy.

---

# G. Scheduling

Schedule publish / unpublish.

Scheduler is platform infrastructure.

Content owns intended times and resulting states.

If clock/job fails: fail closed (remain unpublished). Do not silently go live.

Do not choose Hangfire/Quartz/etc. in this task.

# H. Taxonomy

Tags/categories for editorial navigation and related content.

Not Catalog category (commercial taxonomy).

Mapping via opaque ids / contracts if needed.

No cross-module table joins (T004).

# I. Content Relationships

Related articles, FAQ attached to product **by id**, series.

No ORM navigation into Catalog tables.

Content does not become a second Catalog.

---

# J. Structured vs Rich Content

Typed fields plus constrained rich text.

Not arbitrary HTML/JS as the domain model.

Sanitization at composition / render.

Do not store executable scripts as content truth.

# M. Landing Pages

Landings are Page Composition instances binding Content / Catalog / Media.

---

# N. Page Composition vs Routing

Composition is not the HTTP router.

SEO / routing package owns URL / canonical / hreflang **technical** policy (later P00-14).

Content / Composition supply slugs and metadata **inputs**.

Do not lock routes, host parsing, or sitemap implementation here.

---

# O. Theme Integration

Theme per store (T003) styles approved sections.

Theme does not own the content write model.

Purchased template is adaptation/reference input, not architecture truth (T000).

Do not vendor or integrate Shopeiva in this task.

---

# P. Catalog Integration

Content / PDP may **reference** Product / Brand / Category ids.

Catalog remains product truth (T008).

No SQL/ORM joins across Content and Catalog tables.

PDP copy blocks may reference Content ids; Content does not own Product tables.

---

# Q. Dynamic Collections

Merchandising / query collections are merchandising or catalog projections.

Content does not own product lists as SoT.

Composition may bind a collection id.

Do not redesign merchandising here.

---

# R. Content & Search

Search indexes **published** content feeds (T000: PostgreSQL FTS first, later OpenSearch; no coupling to PG internals).

Search is not CMS.

Unpublished / draft must not leak via search.

Do not implement Search in this task (later P00-15).

Content != SEO Engine

At minimum recommend for ADR:

1. Content != Blog-only; Blog is a type or presentation pattern.
2. Content != Page Composition; landings are composable instances.
3. Content != Catalog != Media != SEO engine.
4. Typed content model, not only untyped JSON as the whole design.
5. Locale variants, not TitleFa / TitleEn / TitleAr columns.
6. Draft vs published revisions; live published copy is not the only editable copy.
7. Approved reusable sections; no arbitrary executable content.
8. Catalog / Media / Search by contract / id / feed only; no cross-module joins.
9. AI / RAG from approved published content only; no unrestricted DB access.
10. Tenant-scoped storefront content; Host is not Content tenant SoT.
11. SpiceDB for author / review / publish / compose; not IsAdmin.
12. SEO technical engine separate; Content supplies metadata inputs.
13. Theme styles approved sections; does not own the write model.
14. Admin is professional authoring, not skeleton CRUD.
15. Accessibility and performance are production constraints on composition.

Do not create the final ADR in this task.
