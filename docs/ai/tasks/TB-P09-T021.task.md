1. New Locked Product Rules
Visibility

The بسته‌بندی مرکزی section is visible ONLY when the Order contains at least 2 distinct Sellers.

If only 1 Seller:

section hidden

no dead placeholder

no disabled button

Eligible Members

Only Seller Shipments that are genuinely ready for central dispatch may be selected.

At minimum:

correct Order

distinct Seller Shipment

pre-dispatch

not cancelled/voided

not delivered

not already active inside another Consolidated Package

fulfillment quantities fully ready according to existing capability model

backend-authoritative CanAddToConsolidatedPackage

Do not infer readiness only from frontend text/status.

Minimum Seller Count

A Consolidated Package requires Shipments from at least 2 distinct Sellers.

Two shipments from one Seller alone are NOT enough for central multi-seller package creation.

Same Order Only

A Consolidated Package may contain Shipments from ONE Order/Checkout only.

Cross-order consolidation is OUT OF SCOPE.

Before Dispatch

Before Consolidated Package dispatch:

it may be cancelled/voided

member Shipments are released from the package

same Shipments may later be selected into a new combination

old Consolidated Package remains historical

do not silently mutate history into a different combination after creation

Preferred correction model:
Cancel old package -> Create new package

After Dispatch

After Consolidated Package dispatch:

membership becomes immutable

no add/remove/rebuild

no simple rollback

Member Shipment Lock

While a Shipment belongs to an ACTIVE pre-dispatch or dispatched Consolidated Package:
direct Shipment operations that would conflict with the package are disabled/rejected.

At minimum block direct:

tracking correction if tracking ownership belongs to central package for final leg

Shipment void

Dispatch

Deliver

UI must show a clear readonly explanation such as:
این مرسوله عضو بسته تجمیعی MP-... است و عملیات ارسال از طریق بسته تجمیعی انجام می‌شود.

Backend guard mandatory.

Orchestration

Consolidated Package must reuse existing Shipment commands.

Central Dispatch:

calls existing Dispatch behavior for each valid member Shipment

no direct status SQL/update shortcut

Central Deliver:

calls existing Deliver behavior for each valid member Shipment

all participating member Shipments must become Delivered through current lifecycle

Consolidated Package does not invent parallel Shipment status truth.

Tracking

Central tracking does NOT delete internal/member tracking history.

member historical tracking remains

central tracking becomes final customer-facing tracking while package is active

no destructive overwrite

Cancelled Order

If whole Order is cancelled before central dispatch:

active pre-dispatch Consolidated Package is voided

membership released

existing T016 Order-cancel orchestration continues

member pre-dispatch Shipments are handled by existing cancel logic

inventory/payment/refund behavior remains unchanged

Returns / Refunds

Returns/Refunds remain line/Seller Shipment/Order based.
Consolidated Package does NOT own return/refund logic.
