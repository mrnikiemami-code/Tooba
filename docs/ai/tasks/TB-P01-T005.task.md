## 3. Mandatory Documentation Standard

For all Tooba-owned production code, every applicable:

```text
Class
Record
Struct
Interface
Enum
Method
Function
Constructor
Property
Indexer
Public delegate
Important internal member
```

must have strong Persian documentation.

For C# public APIs prefer:

```csharp
/// <summary>
/// ...
/// </summary>
```

For parameters/returns/exceptions where behavior is non-trivial, also use:

```csharp
/// <param>
/// <returns>
/// <exception>
```

Comments must explain:

```text
responsibility
contract
important invariants
security/tenant implications when relevant
failure semantics when relevant
why the abstraction exists when non-obvious
```

Weak comments that merely repeat the member name are NOT acceptable.

Example of weak documentation:

```text
"این کلاس TenantContext است."
```

Example of useful documentation:

```text
"زمینهٔ تغییرناپذیر Tenant جاری را پس از resolve امن Host نگهداری می‌کند.
این شناسه مستقل از hostname است و نباید توسط لایه‌های پایین‌تر دوباره از Request استخراج شود."
```

Comments must remain readable and technically precise.

## 12. Architectural Comment Quality

```text

Host is routing input, not durable identity
```

## 13. Security Comments

Security-sensitive code should document why a restriction exists.

Examples:

```text
Forwarded headers accepted only from trusted proxies
Tenant headers/query/cookies are not authority
Unknown tenant resolution fails closed
Connection strings must not be logged
ProblemDetails must not expose implementation details
```

Do not add comments that expose secrets.
