# A. Core Separation

Define:

```text
Inventory
Availability
Reservation
On-hand
Reserved quantity
Available-to-sell (ATS)
Stock identity / sellable
Location / warehouse
Inventory adjustment
Stock movement
Allocation / committed stock
```

Hard rules:

```text
Inventory != Catalog Product
Inventory != Offer
Inventory != Price / Quote
Inventory != Fulfillment shipment
Product.Stock column != Inventory write-model truth
Search/PLP in-stock badge != sell permission
Reservation != silent quantity overwrite
```

Inventory owns the availability and reservation write-model for sellable identities (typically Offer/SKU at a location).

Must not own as SoT: product titles, prices, seller legal identity, payment capture, shipment tracking.

---

# B. Inventory Scope

Inventory is scoped to a sellable (Offer and/or Variant+Seller) within tenant/deployment isolation.

Marketplace: per seller offer. Seller A stock is not Seller B stock.

Single-Store: same seams with an implicit seller and/or location. Do not collapse Inventory into Catalog Product.

Do not treat a template product row as stock.

---

# C. Stock Identity

Stock is identified by sellable id (OfferId and/or VariantId+SellerId) plus location id.

Not identified by:

```text
Product title
Locale
Market as the only key
Seller SKU as the only key (seller SKU is Offer-local; Inventory keys off canonical sellable id)
Host / domain
```

Align with T008: Offer references sellable identity; Offer does not own stock counts.

---

# D. Warehouse / Location Model

Candidate location kinds:

```text
warehouse
store / pickup
virtual / dropship
```

Multi-warehouse readiness without requiring multi-warehouse UX on day one.

Exact location taxonomy:


Do not lock schema. Do not bury location inside Catalog.

# E. Quantity Semantics

Separate conceptually:

```text
on-hand
reserved
available-to-sell
incoming (optional)
```

ATS is derived from a rule, not three independent truths that may drift.

Do not lock formulas or columns. Do not use IEEE float as a quantity type if that would imply money-like float abuse; integer units are the default direction unless later policy says otherwise.

---

# F. Reservation

A reservation is a time-bounded hold against available quantity for a cart/checkout/order line.

Must include conceptually:

```text
reservation id
quantity
sellable id
location (or allocation policy)
owner (cart / checkout / order)
expiry
status
```

Not a stock adjustment that silently loses audit. Not owned by Cart as write-model truth.

---

# G. Reservation Timing

Candidate moments:

```text
add-to-cart
checkout start
payment authorization / capture
```

Tradeoffs: oversell vs abandoned-cart lock.

Exact timing:

```text
NEEDS_LATER_P00_DETAIL
```

Architecture must support expiry and release regardless of which moment is chosen later.

---

# H. Oversell Protection

Fail closed when ATS < requested, unless an explicit backorder/preorder/made-to-order policy applies (section O).

No silent negative ATS as a successful sell.

Concurrency must not double-spend the last unit (section U).

---

# I. Inventory Adjustment

Receipts, counts, damage, returns-to-stock are Inventory commands with reason and audit.

Not Catalog edits. Not “set Product.Stock = n” from Admin as an unofficial path.

---

# J. Stock Movement Ledger Direction

Recommend append-only movement facts (or equivalent) so on-hand is reconcilable.

Exact ledger vs snapshot storage:

```text
NEEDS_LATER_P00_DETAIL
```

Not optional for professional ops. Do not implement a ledger now.

---

# K. Seller / Marketplace Inventory

Each seller’s offer stock is isolated. Seller A cannot consume Seller B.

Catalog Product has no stock field as SoT.

SpiceDB later gates who may adjust which seller/location; do not design the relationship graph in this task.

---

# L. Single-Store Inventory

Same Inventory module. One implicit location/seller is allowed.

Do not merge Inventory into Product. Do not scatter `if (isMarketplace)` as the stock model.

---

# M. Inventory vs Fulfillment

Inventory: can we sell / hold.

Fulfillment: pick/pack/ship of a confirmed order unit.

Shipping a unit decrements or commits reservation via contract/events. Fulfillment does not write Inventory tables.

Do not design Fulfillment in this task.

---

# N. Market / Channel Availability

Inventory quantity ≠ market eligibility.

An item may have stock and still be unsellable in a Market (Offer/Market policy from T008/T009). Both checks are required at quote/cart/checkout.

Locale is not availability. Currency is not stock.

---

# O. Backorder / Preorder / Made-to-Order

Preserve future policies as explicit offer/inventory modes, not negative-stock hacks.

Not implemented now.

Exact modes:

```text
DEFERRED
```

---

# P. Inventory Quote / Availability Check

Synchronous query contract at PDP/cart/checkout:

```text
sellable + quantity + location/policy (+ tenant/seller isolation) → available | deny
```

Search index is not availability SoT. Pricing quote is not a stock check.

No API implementation in this task.

---

# Q. Cart Interaction

Cart holds lines and may request reservation per later policy.

Cart does not own stock counts. Cart does not join Inventory tables.

No Cart schema in this task.

---

# R. Checkout Interaction

Checkout extends or creates reservations. Expiry must cover the payment window or require re-reserve.

Failure releases holds via Inventory commands/events.

No Checkout schema in this task.

---

# S. Order Interaction

On confirm: convert reservation to committed allocation / decrement per policy.

Order snapshots ordered quantity; live stock remains Inventory.

Later catalog/offer/price mutations must not rewrite inventory history via Order.

No Order schema in this task.

---

# T. Payment Interaction

Payment failure / timeout must release reservations (event/reaction). Do not leave orphan holds.

Payment does not own stock. Inventory does not own PSP internals.

No Payment implementation in this task.

---

# U. Concurrency / Idempotency

Reserve / commit / release must be idempotent (reservation id and/or command id).

Concurrent last-item: one winner, one fail-closed.

No cross-module DB lock as the architecture. Align with T004: local ACID inside Inventory; contracts/outbox across modules.

---

# V. Event Model

Facts (conceptual):

```text
reserved
expired
released
committed
adjusted
```

Consumers (conceptual): Cart, Checkout, Order, Search projection, Notifications.

Outbox-ready (T004). Do not implement brokers.

---

# W. Search / PDP / PLP Projection

In-stock badges are projections.

Search must not update Inventory. Stale badge ≠ sell permission; checkout rechecks via Inventory contract.

This task does not design Search, SEO, or UI.

---

# X. Cache

Short TTL and/or versioned availability cache is optional.

Redis is not required initially (T000 caching abstraction). Never cache across tenants or sellers.

Availability cache is commercially sensitive (oversell), not a security identity store.

No cache implementation now.

---

# Y. First-Party Analytics

Stockout and reservation events may emit analytics facts (ids, not dumps).

Analytics is not Inventory SoT. Do not design the analytics pipeline here.

---

# Z. Admin / Seller UX Implications

Seller/Admin adjust via Inventory commands. Lists come from projections/read models.

Forbidden as SoT: `Product.Stock` form field, template SKU stock column, Offer row as the only stock cell.

SpiceDB gates who may adjust which seller/location (T006). Do not implement Admin UI.

---

ERP/WMS behind an adapter. External system is not an excuse for Catalog to hold stock.

# AB. Reconciliation

Periodic compare of ledger vs physical/ERP.

Corrections are Inventory adjustments with audit, not silent Search edits, not Catalog patches.

# AC. Tenant Isolation

Single-Store: stock never leaks across stores.

Marketplace: never across sellers.

Tenant context comes from the platform (T003), not Host parse inside Inventory.

# AG. Decision Summary

Classify:

```text
RECOMMENDED_FOR_ADR
NEEDS_LATER_P00_DETAIL
DEFERRED
```

At minimum recommend for ADR:

1. Inventory owns availability and reservation write-model, not Catalog, Offer, or Price.
2. Marketplace stock is seller/offer-scoped; Seller A cannot consume Seller B.
3. Single-Store keeps Inventory as its own write model; implicit seller/location does not merge Inventory into Product.
4. Reservation is a first-class time-bounded hold with expiry and release, not a silent quantity overwrite.
5. Oversell: fail closed unless an explicit backorder/preorder/made-to-order mode applies.
6. Movement/ledger direction so on-hand is reconcilable.
7. Fulfillment does not own ATS write-model; it collaborates via contracts/events.
8. Cart/Checkout/Order/Payment do not own stock; payment failure releases reservations.
9. Reserve/commit/release are idempotent; last-unit concurrency has one winner.
10. Search/PLP in-stock is a projection; checkout rechecks Inventory.
11. Tenant/seller isolation on all inventory operations; no Host parse inside Inventory.
12. External WMS/ERP behind an adapter; Catalog never holds stock as a sync dump.
13. Market eligibility is not Inventory quantity; both checks are required to sell.
14. Admin/Seller adjust via Inventory commands; `Product.Stock` is forbidden as SoT.

Do not create the final ADR in this task.
