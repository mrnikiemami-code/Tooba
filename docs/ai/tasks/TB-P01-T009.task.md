## Locked Architecture Rules

Enforce:

```text
Modular Monolith
Module owns its Domain/Application/Infrastructure
No foreign-module repository access
No cross-module DbContext access
No cross-module EF navigation
No cross-module SQL JOIN
No shared mega DbContext
No cross-module transaction assumption
Cross-module interaction via contracts/interfaces/events/projections/gateways
Backend module boundary != UI boundary
```

## Module Registration Contract

Create a minimal Tooba-owned module registration abstraction, e.g.:

```text
IToobaModule
```

or equivalent.

It should support clean registration of:

```text
services
module infrastructure
optional endpoints
optional background workers
module contracts
```

Avoid a god-interface.

Host should compose modules explicitly from one composition location.

Do not add reflection-heavy auto-discovery unless clearly justified.

## Dependency Direction

Preferred direction:

```text
Domain
↑
Application
↑
Infrastructure
↑
Host composition
```

Contracts intended for other modules must live in a stable contract surface.

Do NOT allow:

```text
Domain -> Infrastructure
Application -> Host
Module A Infrastructure -> Module B Infrastructure
Module A -> Module B persistence internals
```

Do not turn ModuleContracts into a dumping ground.

No business contracts yet.

## Architecture Tests — Mandatory

Add automated architecture tests that fail when prohibited dependencies appear.

Use a lightweight architecture-testing approach.

You may use a stable analyzer/test package if justified.

At minimum prove:

```text

```

If some rules cannot be fully encoded yet because only PlatformProbe exists, add the executable guard where possible and document the limitation.

## Cross-Module Data Guard

Add a durable rule/test preventing future module projects from directly referencing another module's persistence project.

Future service extraction must remain possible.

Hard rule:

```text
consumer business logic must not depend on in-process implementation details
```

## Host Composition

Host may depend on module Infrastructure to compose the application.

Host must not contain business logic.

Do not move module internals into Host for convenience.
