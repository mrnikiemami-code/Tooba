Replace the temporary in-process integration-event transport from T006 with a real durable MassTransit SQL Transport backed by PostgreSQL.


## 5. Why PostgreSQL SQL Transport

MassTransit SQL Transport must become Tooba's initial durable integration-message transport.

It is NOT the Tooba business database abstraction.

It is infrastructure for:

```text
queues
topics
subscriptions
durable transport messages
consumer delivery
retry/redelivery
error/dead-letter handling
```

Hard rule:

```text
SQL Transport != module business persistence
```

## 18. Retry / Redelivery

Use MassTransit-native transport/consumer retry/redelivery where it replaces equivalent transport-level behavior.

Do not create duplicated retry loops:

```text
T006 retry loop
+
MassTransit immediate retry
+
MassTransit redelivery
```

without a documented policy.

Required distinction:

```text
Outbox delivery retry
= failure publishing from business outbox to transport

Consumer processing retry/redelivery
= failure consuming already transported message
```

Keep these semantics separate.

## 19. Error / Dead-Letter

Do not use the business outbox dead-letter as a replacement for MassTransit consumer `_error`/dead-letter semantics.

Document both failure domains.
