Architect Intent

This task locks and implements the FOUNDATION for Order/Inventory supply semantics.

Order lifecycle must not depend on one historical Reservation instance.
Any operation that requires guaranteed supply must ask Inventory through one canonical capability.

3. Canonical Supply Status

Introduce/reuse business-facing projection equivalent to:

Reserved

AvailableForReacquire

Unavailable

PartiallyUnavailable

Fulfilled

NotApplicable

Meaning:

Reserved: required remaining qty is secured

AvailableForReacquire: no sufficient active hold, but authoritative stock can satisfy all remaining qty

Unavailable: required qty cannot currently be supplied

PartiallyUnavailable: some lines available, some not; diagnostic only, never partial committed recovery

Fulfilled: no remaining qty needs reservation

NotApplicable: cancelled/refunded/terminal state where supply no longer applies

Per-line diagnostics for Admin projection:

human item data

remaining required qty

secured qty

current available-to-reacquire qty

result

unit

No raw reservation GUID in normal UI.

5. Explicit Modes

Support explicit application modes, not hidden heuristics:

CheckOnly

Authoritative supply check, NO mutation.

EnsureReviewHold

For manual payment review. Reuse valid hold; otherwise reacquire only if policy permits.

EnsurePaidDurable

For confirmed payment/customer money received. Reuse valid durable supply; otherwise reacquire if policy permits and make durable.

EnsureFulfillmentSupply

For fulfillment operations requiring secured supply, using current domain rules.

Client/UI must not arbitrarily choose privileged modes; application use-case chooses mode.
