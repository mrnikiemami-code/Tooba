Locked Architecture
A. Template Catalog is separate storage

Operational Catalog remains unchanged:

Product + all existing Product child/translation/media/relation tables

Category + all existing Category child/translation/relation tables

Brand + all existing Brand child/translation/relation tables

Banner + existing Banner structure if Banner is part of current persisted catalog/content model

Template Catalog mirrors these structures into separate Template-prefixed table families.

B. Exact mirror rule

For each mirrored entity family:

keep the SAME business fields

keep the SAME translation structure

keep the SAME child/media/relation semantics

keep the SAME cardinality rules

keep the SAME required/nullable semantics where technically possible

keep equivalent indexes/uniqueness semantics where applicable

The only intentional additional ownership field on each TEMPLATE ROOT table is:

TemplateId

Do NOT add invented fields such as:

IsDemo

DataScope

SeedBatchId

OwnershipState

ClonedFromDemoId

SeedOrigin

arbitrary JSON metadata

The root template table may contain only the normal template identity fields needed to identify/select a template.

C. Operational tables stay lean

No TemplateId / IsDemo / DataScope is added to:

Product

Category

Brand
or their operational child tables.

This is a hard performance/storage lock.

D. Catalog parity

TemplateProduct family mirrors Product family.
TemplateCategory family mirrors Category family.
TemplateBrand family mirrors Brand family.

If current Product has child tables, mirror the relevant child tables too.
If current Category/Brand has Translation tables, mirror them too.

Do not simplify the mirrored model merely because this task has only 15 products.

E. Preview source separation

Fashion preview in Sample mode must read ONLY Template Catalog tables for Fashion.

Operational store data must not appear in Sample mode.

No mixing.
