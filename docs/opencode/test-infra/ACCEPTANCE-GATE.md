# OpenCode acceptance evidence gate
Scope: isolated OpenCode branch, full-stack DEV tasks using the existing Host/Next/tooba_alpha. Do not transfer this governance to Cursor/main.
Before edits: read required source/locks and OpenSpec; record paths/hashes and constraints; prepare a per-ID assertion plan from the immutable issued matrix; architect reviews coverage before the full run. Build test project from exact candidate, preserve logs. Run `node docs/opencode/test-infra/acceptance-gate.cjs --self-test`.
Final: `node docs/opencode/test-infra/acceptance-gate.cjs MATRIX PLAN RUN EVIDENCE_ROOT`.
- MATRIX: immutable issued JSON with taskId and tests[].testId.
- PLAN: taskId, sourceCommit (full candidate SHA), tests[] with testId, scenarioSha256 = SHA256(JSON.stringify(original matrix test object)), assertionIds[] distinct nonempty, optional expectedFacts object keyed by assertionId for static expected values. Freeze assertion plan before implementation; bind final candidate SHA before execution and preserve initial plan provenance.
- RUN: taskId, sourceCommit, hostSha256, nextBuildId, database, testBuildCommit, testBuildSucceeded; tests[] each testId, scenarioSha256, sourceCommit, hostSha256, nextBuildId, status PASS, executed true, evidencePath (relative to evidence root), evidenceSha256, assertions[] each assertionId, pass, expected, observed. For complex predicates use measured operands in actual runner/log plus expected boolean true and independently computed observed boolean. For concurrency use actual successful request's submitted value as expected, SQL/GET value as observed. Each scenario evidence JSON must include testId, scenarioSha256, sourceCommit, assertions; retain raw requests/response/SQL/build logs linked from per-ID evidence.
- The gate checks structure, exact IDs, equality, evidence bytes and declared provenance. It cannot establish that a worker really read a file, executed a test, used an appropriate oracle, served a given build or did not fabricate both expected/observed. Independent architect must inspect runner and raw evidence, verify actual candidate/served build, compare all scenario clauses and forbidden effects. No PASS based on gate alone.
- On context pressure checkpoint per finding (state, evidence, next safe action, source SHA); resume same task. No terminal BLOCKED merely for context pressure; retain genuine safety and owner-approved finite repair gates.
- Current R10 historical evidence remains unchanged; no retroactive PASS. Do not expand product scope; existing owner policy controls remain. The owner must explicitly decide genuinely missing warehouse-sharing policy; fail closed on unknown eligibility.
