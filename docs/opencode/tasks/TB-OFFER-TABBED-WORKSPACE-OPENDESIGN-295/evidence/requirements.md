Design an interactive, self-contained HTML prototype for the TOOBA "Offer create/edit form" using a TABBED WORKSPACE (Persian RTL, Vazirmatn-like, Jalali dates, Toba design-system look, real RTL all controls, correct LTR for English, Persian digits/formatting).

SCOPE (strict): ONLY the offer create/edit form for TWO roles: admin and seller. DO NOT design or include the main offers table, dashboard, panel menu, sidebar, or general shell. Do not redesign existing standard components.

PAGE = three parts:
1) Compact sticky summary HEADER (must NOT take large vertical space and must NOT overlay content): product image, product name, variant, seller, offer code, status badge, buyability, a price summary that ALWAYS shows market + currency (never sum different currencies), and actions «ذخیره تغییرات» + «انصراف».
2) RTL TAB BAR in this exact order: 1 مشخصات آفر · 2 قیمت‌گذاری · 3 تخفیفات · 4 موجودی · 5 ارسال · 6 شرایط فروش · 7 تاریخچه.
3) TAB CONTENT: only the selected tab is shown (a long single scrolling form is FORBIDDEN).

TAB1 مشخصات آفر: seller picker (search-based, server pagination, ≥10k sellers; in SELLER mode identity comes from session and is NOT changeable); advanced PRODUCT picker for ≥1,000,000 products (search by name/code, filters category/brand, server pagination, shows image/name/brand/variant specs/status, has loading/empty/error/retry states, preserves previous selection; a plain dropdown of all products is FORBIDDEN); variant select from valid variants; seller SKU; sales channel per allowed contract; offer id read-only after create. Dependent tabs stay DISABLED until a valid seller+product+variant is chosen; after create, seller+variant are LOCKED.

TAB2 قیمت‌گذاری (optimize for frequent ops): table with columns ارز، مبلغ، بازار، کانال فروش، نوع قیمت، شروع اعتبار، پایان اعتبار، وضعیت قیمت، عملیات. Add-price opens its own panel (currency chosen from the allowed currency source — free typing a currency code is not acceptable, amount, market, channel, base/campaign type, validity range). Support multiple prices and multiple currencies. IRR has no decimals; other currencies per policy. Thousands separators + Persian digits. A saved price currency must not change directly. Overlapping validity ranges must be marked invalid. Base vs campaign prices must be distinguishable. Edit/retire allowed per status and permission; if a contract lacks an op, mark it «نیازمند قرارداد تکمیلی».

TAB3 تخفیفات (Promotion owns discount rules; do not present the offer as the owner): overview of related discounts with status, applied conditions, validity range, a sample final price and allowed ops. Capabilities: percentage; fixed amount + currency; date range; min quantity; min amount + currency; coupon code; priority; market/channel scope; supported customer conditions; related campaign; status (draft/active/…). Show a customer-price PREVIEW (base, discount, final) labelled as a sample (not a guaranteed payable amount). Active discounts are not economically editable.

TAB4 موجودی (multi-warehouse): summary totals (available/reserved/physical) + per-warehouse table (warehouse, physical, reserved, available, operation «اصلاح») with totals from valid positions. Adjust panel: warehouse name, previous, new, delta, reason. Reserved is READ-ONLY; available is COMPUTED read-only; physical must be ≥ reserved; no negative; unit/precision from product; recorded warehouse identity immutable; reason required. Deleting a position without contract/dependency control is forbidden; adding a new position only if a valid contract exists (otherwise mark needs-contract).

TAB5 ارسال: responsibility (فروشنده / پلتفرم / تعیین‌نشده), shipping type, service chosen ONLY from published+allowed services. Show READ-ONLY service info the contract provides (geo scope, prep time, schedule, weight/count, amount conditions, cost, freight payer, free-shipping). Do NOT redefine service/geo/rate/schedule inside the offer. Service select is DISABLED until responsibility is set. Do not show foreign/inactive services. Number of assignable services is not assumed final. Seller vs admin permission differ.

TAB6 شرایط فروش: quantity&unit (unit, decimals, step, rounding READ-ONLY from product; min/max qty + remove-limit editable; weight/volume/length/count must not share one decimal behavior). Returns three modes: default (read-only general policy) / custom (allowed window if seller has authority) / non-returnable (HIDE the return-window field). Lifecycle: Draft/Active/Suspended/Archived; transitions per domain+permission; archived cannot be re-activated; buyability is a COMPUTED state (not a manual toggle) with simple human reasons when not buyable.

TAB7 تاریخچه: ONLY in EDIT mode; timeline of valid changes (event type, actor, Jalali date/time, old/new), event-type filter. NO fake history for new form or unsupported events; sample data clearly marked.

TAB BEHAVIOR (critical): preserve entered data when switching tabs; show an unsaved indicator on tabs with unsaved changes; validation errors mark the tab+field; failed save preserves data; exiting with unsaved changes warns; per-tab loading state; fetch error allows retry without losing other tabs; unauthorized tab denies ops; in edit mode deep-link can open a specific tab. ONE primary action bar only; price/inventory/discount panels may have their own save if the contract allows; do NOT promise a global atomic transaction across domains. Create mode: choose seller/product/variant → validate → enable tabs → fill → save draft or activate if allowed; opening the form must NOT auto-create an empty record; do NOT turn create into a mandatory 7-step wizard.

MOBILE: not a shrunken desktop. Tab bar scrolls horizontally with a clear active tab, primary actions reachable, add panels mobile-sized, min 44px touch targets; must work at 360/390/768/1280/1440 with no horizontal overflow of the whole page. Status must be recognizable beyond color alone. No domain/technical jargon in the UI; keep the word «آفر».

DELIVERY: one self-contained HTML file (assets embedded as data URIs) with an ADMIN mode and a SELLER mode, and CREATE and EDIT states (toggle or tabbed), including the product picker and seller picker modals, and all seven tabs. Put all colors in :root CSS variables (no raw hex outside :root) and add data-od-id to each top-level section. Persian labels. The prototype must demonstrate UX-01..UX-30 (7 tabs, single-tab content, preserve on switch, create with unselected identity, choose product/variant/seller, locked identity in edit, add IRR price, add FX price, invalid validity-range error, percent discount+preview, fixed discount, active-discount edit guard, multi-warehouse, adjust+reason, invalid stock prevention, reserved lock, service gated by responsibility, read-only shipping info, three return modes, decimal qty per policy, non-buyable offer detection, save error preserving data, unsaved-exit warning, history only in edit, seller permission limits, mobile, no overlap/overflow, fa/en, preserve selection across paging, provenance).
